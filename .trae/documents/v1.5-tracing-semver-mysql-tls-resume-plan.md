## 假设与决策

1. **MySQL connection.rs 沿用 SQLite/PG 完全相同的 5 步模式** — 保持三库一致性，不引入新抽象
2. **`threshold()` helper 模式** — 避免 guard 调用点的 `#[cfg]` 分支，feature on/off 共用同一 `QueryGuard::new(sql, threshold)` 签名
3. **SemVer 迁移指南采用"1 minor deprecation 期"策略** — vN.x 标记 `#[deprecated]` → vN.(x+1) 移除
4. **版本号 1.4.1 → 1.5.0** — minor bump（新增 feature + 文档，无 breaking change）
5. **路径依赖版本字符串同步更新** — `rust-ef = { version = "1.4.0", ... }` → `"1.5.0"`（sqlite/postgres/mysql 的 Cargo.toml + core 的 rust-ef-macros 依赖）
6. **CHANGELOG v1.5.0 条目用中文** — 与 v1.4.0/v1.4.1 风格一致

### Step 2：创建 SemVer 严格化迁移指南（Phase 3 — 文档）

**新文件**：`docs/v1.5-semver-migration-guide.md`

内容结构（中文）：
1. **背景** — v1.0-v1.4 minor 版本含 breaking change 的历史回顾（`#[entity_config]`→`#[entity]`、rust-dix 0.6、`begin_transaction` 签名变更）
2. **v1.5 SemVer 严格化策略**
   - 1 minor deprecation 期：vN.x 标记 `#[deprecated(note="...")]` → vN.(x+1) 移除
   - breaking change 必须在 CHANGELOG 显式标注 `BREAKING`
   - 新增 API 优先用 `#[must_use]` / `#[deprecated]` 引导
3. **当前 breaking change 清单与迁移路径**（v1.0→v1.5 历史变更归类）
4. **deprecation 期示例代码**（`#[deprecated]` 用法 + 编译期警告引导）
5. **版本号约定**（SemVer 2.0.0 严格解读：minor 不含 breaking change）
6. **未来 breaking change 预留**（v2.0 候选项：Arc-wrapped EntityTypeMeta、async trait 原生语法迁移）
