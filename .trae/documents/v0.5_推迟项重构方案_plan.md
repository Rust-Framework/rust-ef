# rust-ef v0.5+ 推迟项重构方案

> 版本: v0.5 路线图（覆盖 8 项 v0.4 推迟项，按难度分三阶段）
> 制定日期: 2026-06-26
> 依据: `统一linq宏DSL改造计划_plan.md` §5.3 推迟项 + v3 G11/G12 用户反馈 + 代码库实际架构调研
> 决策: 全部 8 项纳入；架构性变更采用一步到位代理式路径

---

## 一、执行摘要

本方案覆盖 v0.4 推迟的全部 8 项特性，按难度与依赖关系分三阶段递进：

| 阶段 | 版本 | 特性 | 难度 | 依赖 |
|---|---|---|---|---|
| **Phase 1** | v0.5 | G1: `QueryBuilder: Clone` | 低 | 无 |
| | v0.5 | G2: `having` 嵌套表达式 | 中 | 无 |
| **Phase 2** | v0.6 | G3: 强类型元组投影 | 中-高 | G1（Clone 支持投影分叉） |
| | v0.6 | G4: `linq!` 类型推断 + let-binding | 高 | G3（字段类型别名基础设施） |
| **Phase 3** | v0.7+ | G5: 子查询 / 关联过滤 | 高 | G4（闭包类型解析） |
| | v0.7+ | G6: 代理式实体自动跟踪 | 极高 | G7（Identity Map 基础） |
| | v0.7+ | G7: Lazy Loading + Identity Map | 极高 | G6（代理实体结构） |
| | v0.7+ | G8: 导航 Fixup | 极高 | G6+G7（双向导航 + 跟踪） |

**依赖链核心**: G3 为 G4 提供字段类型别名基础设施 → G4 为 G5 提供闭包类型解析 → G7 为 G6 提供 Identity Map → G6+G7 为 G8 提供双向导航 Fixup。

## 二、当前架构分析

### 2.1 linq! 宏架构（`crates/macros/src/linq.rs`, 1628 行）

**解析流程**: `LinqInput` enum 分派 Form A/B/C → `parse_query` 提取 source/entity/closure → `compile_expr` 编译表达式树 → 生成 `*_internal` 方法链。

**关键限制**:
- `source_entity_type`（行 350-377）: 遍历方法调用链查找 turbofish `::<Type>`，裸变量（`let set = ...; linq!(set; ...)`）无法解析
- `extract_field`（行 1503-1510）: 生成 `Entity::COLUMN_<NAME>` 常量引用，**不携带 Rust 类型信息**
- `compile_method`（行 1280-1487）: 仅识别标量字段比较 + `contains`/`starts_with`/`is_null` 等，**无子查询/关联过滤**

### 2.2 实体跟踪架构（`crates/core/src/tracking.rs` + `db_set.rs`）

**当前模式**: 手动快照式
- `DbSet<T>::entries: Vec<TrackedEntry<T>>` 持有实体实例 + `Option<HashMap<String, DbValue>>` 原始快照
- `attach()`: push 实体 + 快照，状态 `Unchanged`
- `detect_changes()`: 全量对比 `snapshot()` vs `original`，差异则标 `Modified`
- `save_changes()`: 自动调 `detect_changes` → 按 Added/Modified/Deleted 分组 → `ChangeExecutor` 生成 SQL

**关键限制**:
- 无查询自动跟踪（需显式 `attach()`）
- 无 Identity Map（每次查询返回新实例）
- 无属性 setter 拦截（全量快照对比 O(n)）
- 无导航 Fixup（`inverse_navigation` 始终 `None`）

### 2.3 导航属性架构（`crates/core/src/relations.rs` + `navigation_loader.rs`）

**当前模式**: 哑容器 + Eager Loading
- `BelongsTo<T>`/`HasMany<T>`/`HasOne<T>`: 纯 `Option<Box<T>>`/`Vec<T>` 容器，不持有 DbContext 引用
- `include`: 编译期生成 `include_internal(nav_const)` 调用 → 运行时 `load_includes` 批量查询
- `Clone` 故意清空内部（避免深拷贝导航数据）

**关键限制**:
- 无 Lazy Loading（容器不持上下文，无法自行查询）
- 无「未加载」vs「加载了但为空」状态区分
- `Send + Sync` 约束与内部可变性冲突

## Phase 1: v0.5 低难度项

### G1. `QueryBuilder: Clone`

**文件**: `crates/core/src/query.rs`

**现状**: `QueryBuilder<T>`（行 468-475）未派生 `Clone`，尽管所有字段（`QueryState: Clone`、`Option<Arc<...>>: Clone`、`PhantomData: Clone`）均已 Clone。链式方法均为 `mut self -> Self`（move 语义）。

**改动**:

#### G1.1 为三个 Builder 派生 Clone

```rust
// query.rs:468
#[derive(Clone)]
pub struct QueryBuilder<T: IEntityType> { ... }

// query.rs:1352
#[derive(Clone)]
pub struct SelectQueryBuilder<T: IEntityType> { ... }

// query.rs:1273
#[derive(Clone)]
pub struct ExecuteUpdateBuilder<T: IEntityType> { ... }
```

#### G1.2 优化 `single`/`single_or_default` 语义

当前 `take(2)` + `to_list` 是为避免 Clone 的变通。加 Clone 后可改为更清晰的 count + fetch:

```rust
// query.rs:1151 - single
pub async fn single(self) -> EFResult<T> {
    let count = self.clone().count().await?;
    if count > 1 {
        return Err(EFError::Query("Sequence contains more than one element".into()));
    }
    if count == 0 {
        return Err(EFError::NotFound("Sequence contains no elements".into()));
    }
    self.first().await
}

// query.rs:1168 - single_or_default
pub async fn single_or_default(self) -> EFResult<Option<T>> {
    let count = self.clone().count().await?;
    if count > 1 {
        return Err(EFError::Query("Sequence contains more than one element".into()));
    }
    self.first_or_default().await
}
```

**注意**: `count()` 会执行一次 `SELECT COUNT(*)`，`first()` 再执行一次 `SELECT ... LIMIT 1`——共 2 次查询 vs 当前 1 次。**保留 `take(2)` 方案作为默认**，Clone 仅用于「builder 复用」场景（如全局 query_filter 叠加）。

```bash

cargo clippy -p rust-ef -- -D warnings
```

### G2. `having` 嵌套表达式

**文件**: `crates/macros/src/linq.rs`、`crates/core/src/query.rs`

**现状**: `having` 仅支持 `agg(col) op value` 形式（`parse_having_rest` 行 590-662）。不支持布尔组合、嵌套聚合、列表达式。

**改动**:

#### G2.1 新增 `HavingExpr` AST（query.rs）

```rust
/// AST node for having expressions, supporting boolean combinations and nested aggregates.
#[derive(Debug, Clone)]
pub enum HavingExpr {
    /// `agg(col) op value` — 基础比较
    Compare { agg: AggKind, col: String, op: CompareOp, value: DbValue },
    /// `expr AND expr`
    And(Box<HavingExpr>, Box<HavingExpr>),
    /// `expr OR expr`
    Or(Box<HavingExpr>, Box<HavingExpr>),
    /// `NOT expr`
    Not(Box<HavingExpr>),
    /// `agg(col) op agg(col2)` — 聚合间比较
    CompareAgg { left_agg: AggKind, left_col: String, op: CompareOp, right_agg: AggKind, right_col: String },
}

#[derive(Debug, Clone, Copy)]
pub enum AggKind { Count, Sum, Avg, Min, Max }

#[derive(Debug, Clone, Copy)]
pub enum CompareOp { Eq, Ne, Gt, Ge, Lt, Le }
```

#### G2.2 `HavingExpr::to_sql` 编译方法

```rust
impl HavingExpr {
    /// 递归生成 SQL 片段，参数 push 到 `params`。
    pub fn to_sql(&self, params: &mut Vec<DbValue>) -> String {
        match self {
            Self::Compare { agg, col, op, value } => {
                params.push(value.clone());
                format!("{}({}) {} ?", agg.sql_name(), col, op.sql_name())
            }
            Self::And(l, r) => format!("({} AND {})", l.to_sql(params), r.to_sql(params)),
            Self::Or(l, r) => format!("({} OR {})", l.to_sql(params), r.to_sql(params)),
            Self::Not(e) => format!("NOT ({})", e.to_sql(params)),
            Self::CompareAgg { left_agg, left_col, op, right_agg, right_col } => {
                format!("{}({}) {} {}({})", left_agg.sql_name(), left_col, op.sql_name(), right_agg.sql_name(), right_col)
            }
        }
    }
}
```

#### G2.3 宏侧扩展 `having` 解析

**文件**: `crates/macros/src/linq.rs`

将 `parse_having_rest`（行 590-662）从「单比较」扩展为「表达式树解析」:

```rust
/// Parses having expression supporting: agg(col) op value, AND, OR, NOT, agg op agg
fn parse_having_rest(input: ParseStream) -> SynResult<LinqClause> {
    let expr = parse_having_or(input)?;
    Ok(LinqClause::HavingExpr { expr })
}

fn parse_having_or(input: ParseStream) -> SynResult<HavingExprAst> {
    let mut left = parse_having_and(input)?;
    while input.peek(Token![||]) {
        let _or: Token![||] = input.parse()?;
        let right = parse_having_and(input)?;
        left = HavingExprAst::Or(Box::new(left), Box::new(right));
    }
    Ok(left)
}

fn parse_having_and(input: ParseStream) -> SynResult<HavingExprAst> {
    let mut left = parse_having_not(input)?;
    while input.peek(Token![&&]) {
        let _and: Token![&&] = input.parse()?;
        let right = parse_having_not(input)?;
        left = HavingExprAst::And(Box::new(left), Box::new(right));
    }
    Ok(left)
}

fn parse_having_not(input: ParseStream) -> SynResult<HavingExprAst> {
    if input.peek(Token![!]) {
        let _not: Token![!] = input.parse()?;
        let inner = parse_having_not(input)?;
        return Ok(HavingExprAst::Not(Box::new(inner)));
    }
    parse_having_compare(input)
}
// parse_having_compare 复用现有 agg(col) op value 逻辑，
// 新增 agg(col) op agg(col) 分支
```

**宏 AST → 代码生成**: 展开为 `HavingExpr` 构造代码:

```rust
LinqClause::HavingExpr { expr } => {
    let having_code = compile_having_expr(&expr, &ctx)?;
    chain = quote! { #chain .having_expr_internal(#having_code) };
}

fn compile_having_expr(ast: &HavingExprAst, ctx: &LinqCtx) -> SynResult<TokenStream2> {
    match ast {
        HavingExprAst::Compare { agg, col, op, value } => {
            let col_const = extract_field(ctx, col)?;
            let val = extract_value(value)?;
            let agg_kind = agg_kind_ident(agg);
            let op_ident = op_ident(op);
            quote! { rust_ef::query::HavingExpr::Compare { agg: #agg_kind, col: #col_const.to_string(), op: #op_ident, value: DbValue::from(#val) } }
        }
        HavingExprAst::And(l, r) => {
            let lc = compile_having_expr(l, ctx)?;
            let rc = compile_having_expr(r, ctx)?;
            quote! { rust_ef::query::HavingExpr::And(Box::new(#lc), Box::new(#rc)) }
        }
        // Or, Not, CompareAgg 同理
    }
}
```

#### G2.4 QueryBuilder 侧 `having_expr_internal`

```rust
// query.rs
pub fn having_expr_internal(mut self, expr: HavingExpr) -> Self {
    let mut params = Vec::new();
    let sql = expr.to_sql(&mut params);
    self.state.havings.push(sql);
    self.state.parameters.extend(params);
    self
}
```

#### G2.5 兼容性

保留现有 `having_internal(agg, col, op, value)` 作为 `HavingExpr::Compare` 的快捷方式，内部转为 `HavingExpr` 调用 `having_expr_internal`。现有 `having count(b.id) > 1` 语法不受影响。

## Phase 2: v0.6 中高难度项

### G3. 强类型元组投影

**文件**: `crates/macros/src/entity.rs`、`crates/macros/src/linq.rs`、`crates/core/src/query.rs`、`crates/core/src/entity.rs`

**现状**: `select (b.id, b.title)` → `select_internal(&[&str])` → `SelectQueryBuilder::to_list()` 返回 `Vec<Vec<String>>`，丢失所有类型信息。

**改动**:

#### G3.1 `#[derive(EntityType)]` 生成字段类型别名（entity.rs）

为每个标量字段生成 `type` 别名:

**宏侧生成逻辑**（entity.rs 在遍历 fields 时）:

#### G3.2 宏侧 `select` 展开携带类型信息（linq.rs）

### G4. `linq!` 类型推断 + let-binding

**文件**: `crates/macros/src/linq.rs`、`crates/core/src/query.rs`、`crates/core/src/db_set.rs`

**现状**: 
- `source_entity_type`（linq.rs:350-377）遍历方法链找 turbofish，裸变量无法解析
- `parse_typed_closure` 要求 `|b: Blog|` 显式类型标注
- `parse_untyped_closure`（`|b|`）仅当 source 是裸类型路径（`Blog, |b| ...`）时工作

**改动方案: Trait-based 延迟解析**

#### G4.1 新增 `LinqSource` trait（entity.rs 或新文件）

```rust
/// Marker trait that exposes the entity type associated with a query source.
/// Implemented by `DbSet<T>` and `QueryBuilder<T>`.
pub trait LinqSource {
    type Entity: IEntityType;
}

impl<T: IEntityType> LinqSource for DbSet<T> {
    type Entity = T;
}

impl<T: IEntityType> LinqSource for QueryBuilder<T> {
    type Entity = T;
}
```

#### G4.2 宏侧: 裸变量 source 展开为 trait 方法调用

修改 `parse_query` 的 `source; clauses` 分支（linq.rs:311-323）:

```rust
// 当 source_entity_type 对裸变量失败时，不报错，
// 而是展开为依赖 trait 的延迟解析
let entity = match source_entity_type(&first) {
    Ok(ty) => ty,
    Err(_) => {
        // 裸变量路径: 生成占位类型，依赖 LinqSource trait 在类型检查时解析
        // 使用一个「类型 holes」占位
        return Ok(QueryInput {
            source: Some(first),
            entity: syn::parse_quote! { __LinqSourceEntity },
            where_param: None,
            where_body: None,
            order: None,
            clauses,
            // 标记需要 trait 解析
            use_trait_resolution: true,
        });
    }
};
```

**展开代码生成**:

当 `use_trait_resolution: true` 时，宏生成:

```rust
// linq!(set; order_by b.rating desc) 展开为:
{
    use rust_ef::LinqSource;
    fn __linq_with_source<S: LinqSource>(source: S) -> impl std::future::Future<Output = Vec<<S as LinqSource>::Entity>> {
        let entity_type_id = std::any::TypeId::of::<<S as LinqSource>::Entity>();
        // 在运行时通过 TypeId 查 entity_meta...
        // 问题: COLUMN_RATING 常量需要具体类型名，trait 无法提供
    }
    __linq_with_source(set)
}
```

#### G4.3 核心障碍与解决方案

**障碍**: `extract_field` 生成 `Blog::COLUMN_RATING` 引用，需要**具体类型名**，trait 只提供 `S::Entity` 抽象类型。

**解决方案: 字段常量 trait 化**

为 `IEntityType` 增加 `COLUMN_*` 的 trait 方法:

```rust
pub trait IEntityType {
    // 现有方法...

    /// Get column constant by field name at runtime.
    fn column_for_field(field_name: &str) -> Option<&'static str>;

    /// Get all field-to-column mappings.
    fn field_column_map() -> &'static [(&'static str, &'static str)];
}
```

`#[derive(EntityType)]` 自动实现:

```rust
impl IEntityType for Blog {
    fn column_for_field(field_name: &str) -> Option<&'static str> {
        match field_name {
            "blog_id" => Some(Self::COLUMN_BLOG_ID),
            "title" => Some(Self::COLUMN_TITLE),
            "rating" => Some(Self::COLUMN_RATING),
            _ => None,
        }
    }
    fn field_column_map() -> &'static [(&'static str, &'static str)] {
        &[
            ("blog_id", Self::COLUMN_BLOG_ID),
            ("title", Self::COLUMN_TITLE),
            ("rating", Self::COLUMN_RATING),
        ]
    }
}
```

#### G4.4 宏侧: 字段引用改为运行时查表

当 `use_trait_resolution: true` 时，`extract_field` 不生成 `Blog::COLUMN_RATING`，而是生成:

```rust
// 编译期: 提取字段名字符串 "rating"
// 展开为:
<source_entity>::column_for_field("rating").unwrap()
```

**但问题**: 宏不知道 source_entity 的具体类型（是 `set` 的泛型参数）。

**最终方案: 闭包参数类型推断**

利用 G3 的字段类型别名基础设施，修改宏的闭包解析:

```rust
// linq!(set, |b| b.rating > 5) 
// 宏展开为:
{
    fn __infer_entity<S: rust_ef::LinqSource>(source: S, f: impl Fn(&<S as rust_ef::LinqSource>::Entity) -> bool)
        -> rust_ef::QueryBuilder<<S as rust_ef::LinqSource>::Entity>
    {
        source.query().filter(f)
    }
    __infer_entity(set, |b| b.rating > 5)
}
```

这样闭包参数 `b` 的类型由 `S::Entity` 推断，用户无需写 `|b: Blog|`。

**但**: `b.rating > 5` 中的 `b.rating` 需要编译期解析为列常量——如果 `b` 的类型是 `<S as LinqSource>::Entity`（泛型），编译器不知道有 `rating` 字段。

**结论**: 纯类型推断在 Rust proc-macro 体系下**不可行**（宏展开先于类型检查，拿不到泛型参数的具体类型）。

#### G4.5 实际可行方案: `linq!` 第二参数显式注入

```rust
// 用户写:
let set = ctx.set::<Blog>();
linq!(set, Blog; order_by b.rating desc)
// 或:
linq!(set: Blog; order_by b.rating desc)
```

宏解析 `set: Blog` 或 `set, Blog` 时:
1. `set` 作为 source 表达式（运行时求值）
2. `Blog` 作为实体类型（编译期解析字段常量）

**宏侧改动**:

```rust
fn parse_query(input: ParseStream) -> SynResult<QueryInput> {
    // ... 现有逻辑 ...

    // source; clauses 分支扩展:
    if input.peek(Token![;]) {
        let entity = source_entity_type(&first)
            .or_else(|_| {
                // 尝试解析 source : Type 形式
                if input.peek(Token![:]) {
                    let _colon: Token![:] = input.parse()?;
                    let ty: Type = input.parse()?;
                    // 消耗可能的 ; 
                    return Ok(ty);
                }
                Err(syn::Error::new_spanned(&first, "source must contain turbofish or explicit type annotation"))
            })?;
        // ...
    }
}
```

#### G4.6 闭包类型标注省略

利用 G4.3 的 `column_for_field` 运行时查表:

```rust
// linq!(ctx.set::<Blog>(), |b| b.rating > 5)
// 宏展开:
ctx.set::<Blog>().query().filter(|b: &Blog| {
    // b.rating 通过字段名查表
    // 但 b.rating 是 Rust 字段访问，编译器需要知道 b 的类型
    b.rating > 5
})
```

**问题**: `b.rating` 是 Rust 字段访问语法，编译器**必须**知道 `b` 的类型才能解析。如果省略 `: Blog`，编译器无法推断 `b` 的类型（filter 闭包的参数类型来自 `QueryBuilder<T>` 的 `T`，但 `T` 在闭包定义时还未绑定）。

**可行方案**: 让 `filter` 方法签名约束闭包参数类型:

```rust
impl<T: IEntityType> QueryBuilder<T> {
    pub fn filter<F>(self, f: F) -> Self
    where F: Fn(&T) -> bool + 'static
    { ... }
}
```

这样 `|b| b.rating > 5` 中 `b` 的类型由 `Fn(&T)` 约束推断为 `&Blog`。

**但**: `linq!(ctx.set::<Blog>(), |b| b.rating > 5)` 宏需要先把 `b.rating > 5` 编译成 `BoolExpr`，而编译发生在宏展开时（编译期），此时 `b` 的类型还未被类型检查器解析。

**最终结论**: 类型推断（省略 `: Blog`）在当前 proc-macro 架构下**不可行**。实际方案:
1. **let-binding**: 支持 `linq!(set: Blog; ...)` 显式注入类型（G4.5）
2. **闭包省略类型**: 保持 `|b: Blog|` 要求（common-pitfalls #3 已文档化）
3. **Form A 无 source**: `linq!(|b: Blog| b.rating > 5)` 保持显式类型

### G6. 代理式实体自动跟踪

**文件**: `crates/macros/src/entity.rs`（大改）、`crates/core/src/entity.rs`、`crates/core/src/tracking.rs`、`crates/core/src/db_set.rs`、`crates/core/src/db_context.rs`

**现状**: 实体为普通 struct（`pub rating: i32`），无 setter 拦截；`ChangeTracker` 为手动快照式。

**改动方案: 一步到位代理式**

#### G6.1 `TrackedField<T>` 包装类型

```rust
// crates/core/src/tracked_field.rs (新文件)
use std::cell::Cell;
use std::sync::atomic::{AtomicU64, Ordering};

/// Global tracker ID generator
static TRACKER_ID: AtomicU64 = AtomicU64::new(0);

/// A field wrapper that records mutations for change tracking.
/// Replaces `pub rating: i32` with `pub rating: TrackedField<i32>`.
pub struct TrackedField<T> {
    value: T,
    /// Tracker entry ID; None = untracked
    tracker_id: Cell<Option<u64>>,
    /// Field name in the entity
    field_name: &'static str,
}

impl<T: Clone> TrackedField<T> {
    pub fn new(value: T, field_name: &'static str) -> Self {
        Self { value, tracker_id: Cell::new(None), field_name }
    }

    pub fn get(&self) -> &T { &self.value }

    pub fn set(&self, new_value: T) {
        // Notify tracker of change
        if let Some(id) = self.tracker_id.get() {
            TRACKER.with(|t| {
                t.borrow_mut().mark_modified(id, self.field_name);
            });
        }
        // SAFETY: This is the interior mutability pattern.
        // TrackedField is only used within DbContext which is !Sync per-thread.
        unsafe {
            let ptr = &self.value as *const T as *mut T;
            *ptr = new_value;
        }
    }
}
```

**注意**: `unsafe` 块用于绕过 `&self` 的不可变性。更安全的替代方案是 `RefCell<T>`，但会导致 `DbSet<T>: !Sync`。`thread_local! TRACKER` 避免了 `Rc<RefCell<>>` 的 `!Send` 问题。

    pub rating: f64,

pub trait ITrackedBlog {
    fn blog_id(&self) -> i32;
    fn set_blog_id(&mut self, v: i32);
    fn title(&self) -> &str;
    fn set_title(&mut self, v: String);
    // ...
}

**问题**: 用户直接写 `blog.rating = 99` 不会经过 setter，跟踪失效。除非:

- 或使用 `#[derive(EntityType)]` 生成 setter 并要求用户用 `blog.set_rating(99)`

#### G6.4 最终方案: `EntityRef<T>` 句柄模式

不修改实体 struct 本身，而是通过 `EntityRef<T>` 句柄间接访问:

```rust
/// A tracked reference to an entity.
/// Field mutations through this handle are automatically recorded.
pub struct EntityRef<'a, T: IEntityType> {
    entity: &'a mut T,
    tracker: &'a RefCell<LocalTracker>,
    entity_id: u64,
}

impl<'a, T: IEntityType> std::ops::Deref for EntityRef<'a, T> {
    type Target = T;
    fn deref(&self) -> &T { self.entity }
}

impl<'a, T: IEntityType> std::ops::DerefMut for EntityRef<'a, T> {
    fn deref_mut(&mut self) -> &mut T {
        // 标记整个实体为 Modified (粗粒度)
        self.tracker.borrow_mut().mark_modified(self.entity_id, "*");
        self.entity
    }
}

// DbSet 提供 entry() 方法:
impl<T: IEntityType> DbSet<T> {
    pub fn entry(&mut self, idx: usize) -> EntityRef<'_, T> {
        EntityRef {
            entity: &mut self.entries[idx].entity,
            tracker: &self.local_tracker,
            entity_id: self.entries[idx].id,
        }
    }
}

// 使用:
let mut blog = ctx.set::<Blog>().entry(0);
blog.rating = 99;  // 通过 DerefMut，自动标记 Modified
ctx.save_changes().await?;
```

**优点**: 不改变实体 struct 定义，不改变字段访问语法。
**缺点**: 必须通过 `entry()` 获取句柄，不能直接 `blog.rating = 99`（除非 `DbSet` 持有 `&mut`）。

#### G6.5 Identity Map 实现

```rust
// crates/core/src/identity_map.rs (新文件)
use std::collections::HashMap;
use std::any::TypeId;

pub struct IdentityMap {
    /// TypeId -> (PkValue -> EntityId in DbSet)
    entries: HashMap<TypeId, HashMap<DbValue, usize>>,
}

impl IdentityMap {
    pub fn get_or_attach<T: IEntityType + IFromRow>(
        &mut self,
        db_set: &mut DbSet<T>,
        row: &Row,
        pk_value: &DbValue,
    ) -> EFResult<usize> {
        let type_id = TypeId::of::<T>();
        let map = self.entries.entry(type_id).or_default();
        if let Some(&idx) = map.get(pk_value) {
            return Ok(idx);  // 返回已有实例索引
        }
        let entity = T::from_row(row)?;
        let idx = db_set.attach(entity);
        map.insert(pk_value.clone(), idx);
        Ok(idx)
    }
}
```

### G7. Lazy Loading + Identity Map

**文件**: `crates/core/src/relations.rs`（大改）、`crates/core/src/navigation_loader.rs`、`crates/macros/src/entity.rs`

**现状**: `BelongsTo<T>`/`HasMany<T>`/`HasOne<T>` 为哑容器，不持上下文引用。

**改动方案: 智能导航包装类型**

#### G7.1 `LazyBelongsTo<T>` 类型

```rust
// crates/core/src/relations.rs
use std::cell::RefCell;
use std::sync::Arc;

pub struct LazyBelongsTo<T: IEntityType> {
    inner: RefCell<LazyState<T>>,
    context: Weak<RefCell<DbContextInner>>,
    fk_value: DbValue,
    navigation: NavigationMeta,
}

enum LazyState<T> {
    NotLoaded,
    Loading,
    Loaded(Option<Box<T>>),
    Error(String),
}

impl<T: IEntityType + IFromRow> LazyBelongsTo<T> {
    pub fn get(&self) -> EFResult<Option<&T>> {
        let mut state = self.inner.borrow_mut();
        match &*state {
            LazyState::Loaded(opt) => return Ok(opt.as_deref()),
            LazyState::NotLoaded => {
                *state = LazyState::Loading;
            }
            _ => return Err(...),
        }
        // 执行查询
        if let Some(ctx) = self.context.upgrade() {
            let ctx = ctx.borrow();
            let entity = ctx.find_by_pk::<T>(&self.fk_value)?;
            *state = LazyState::Loaded(entity.map(Box::new));
            match &*state {
                LazyState::Loaded(opt) => return Ok(opt.as_deref()),
                _ => unreachable!(),
            }
        }
        Err(EFError::Tracking("Context dropped".into()))
    }
}
```

## 五、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| G6 `unsafe` 块在 `TrackedField::set` 中 | 内存安全风险 | 优先用 `EntityRef<T>` 句柄模式（无 unsafe）；`TrackedField` 作为备选 |
| G7 `RefCell` `!Sync` 与 `DbContext: Send + Sync` 冲突 | 编译失败 | 使用 `parking_lot::RwLock` 替代 `RefCell` |
| G6 `DbContext` 循环引用（`QueryBuilder` → `DbContext` → `DbSet` → `QueryBuilder`） | 内存泄漏 | 使用 `Weak<RefCell<DbContext>>` 弱引用 |
| G4 proc-macro 无法获取变量类型 | 不可行 | 退化为 `linq!(set: Blog; ...)` 显式注入类型 |
| G5 子查询 SQL 生成复杂 | 正确性风险 | 充分集成测试 + 与手写 SQL 对比 |
| G6/G7 架构性变更破坏现有 API | 重大破坏性 | 保留 `BelongsTo`/`HasMany` 作为非 lazy 默认；`#[lazy]` 属性 opt-in |
| Phase 3 工作量极大 | 工期超预期 | 分多个 v0.7.x 小版本渐进发布 |
