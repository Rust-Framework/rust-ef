### Phase C — M4 P1 性能

#### C1. M4.1 SQLite spawn_blocking

**文件**：[crates/sqlite/src/connection.rs](file:///d:/GitCode/RF/rust-ef/crates/sqlite/src/connection.rs)（line 59-87）

`execute`/`query` 内同步 rusqlite 调用（`execute_sync`/`query_sync`）包入 `tokio::task::spawn_blocking`，避免阻塞 tokio runtime。`pool.get()` 阻塞调用同样包入。

```rust
async fn query(&mut self, sql: &str, params: &[DbValue]) -> EFResult<Vec<Vec<DbValue>>> {
    let _guard = rust_ef::observability::QueryGuard::new(sql, self.threshold());
    match &self.inner {
        SqliteConnectionInner::Pooled(m) => {
            // PooledConnection 是 Send, 可 spawn_blocking
            let conn = m.lock().unwrap_or_else(|p| p.into_inner());
            // 闭包捕获 sql(String) + params(Vec<DbValue>) — 均 Send
            let sql_owned = sql.to_string();
            let params_owned = params.to_vec();
            tokio::task::spawn_blocking(move || query_sync(&conn, &sql_owned, &params_owned))
                .await
                .map_err(|e| EFError::Query(format!("spawn_blocking join error: {}", e)))?
        }
        SqliteConnectionInner::Shared(m) => {
            // TokioMutex 已在 async 上下文, 无需 spawn_blocking
            let conn = m.lock().await;
            query_sync(&conn, sql, params)
        }
    }
}
```

> 注意：`PooledConnection` 持有 `r2d2` 的连接引用，`spawn_blocking` 闭包需 `'static` + `Send`。需将 `&conn` 改为 owned（`PooledConnection` 本身 owned，`&Connection` 通过 `&*conn` 获取）。若 `PooledConnection` 非 `Send`，则需在 spawn_blocking 内 `pool.get()`。验证 r2d2_sqlite 的 `PooledConnection` Send 性。

## Assumptions & Decisions

1. **M2 Layer 2-7 原子修改**：改 `IAsyncConnection::query` 签名后所有 provider+consumer+测试同时失效，必须同步修改。按 A1→A2→A3→A4 顺序逐文件改，最后一次性 `cargo build` 定位遗漏。

2. **`unwrap_or_default` 统一容错**：与原 `unwrap_or(0)` 语义等价（数值→0、bool→false、String→""），统一所有类型的容错模式。

3. **`ParseFromDb` 完全删除**：v1.6 接受破坏性变更。保留会导致两套并行解析路径（String-based + DbValue-based），违背"禁止补丁式修改"。

4. **M4.1 spawn_blocking 需验证 Send 性**：r2d2_sqlite 的 `PooledConnection` 是否 `Send` 决定能否移入 spawn_blocking 闭包。若非 Send，则在闭包内 `pool.get()`。

5. **M4.3 批量 include 优先正确性**：ThenInclude 语义复杂，先实现"收集同层子实体 → 批量加载 → 回填"的正确版本，性能优化后续迭代。

6. **M5.3 Upsert 不加 EntityState 变体**：避免破坏现有枚举 match。用 `is_upsert` flag 在 change_executor 内分流。

7. **M3.3 错误结构化是 additive**：新增可选字段，保留现有 `From<String>` 构造便利。非破坏性变更。
