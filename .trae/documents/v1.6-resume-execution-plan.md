### Phase B — M3 P1 稳定性

#### B1. M3.1 MySQL 未知类型告警

**文件**：[crates/mysql/src/row_conversion.rs](file:///d:/GitCode/RF/rust-ef/crates/mysql/src/row_conversion.rs)（line 64-67）

**修改**：在 `cell_to_db_value` 最后回退（返回 `DbValue::Null`）前，加 tracing feature 门控的告警：

```rust
#[cfg(feature = "tracing")]
{
    let col_name = row.columns().get(col_idx).map(|c| c.name()).unwrap_or("unknown");
    tracing::warn!(column = col_name, index = col_idx, "MySQL column type unrecognized, returning NULL");
}
DbValue::Null
```

**为什么**：当前未知类型静默返回 Null，生产环境难以排查数据丢失。tracing 门控保证非 tracing feature 无开销。

#### B2. M3.2 DI 工厂 panic 审查

**文件**：[crates/core/src/db_context.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/db_context.rs)（line 442-459）

**修改**：审查 `from_options` 全路径 + `MetadataCache` 访问路径，确认无 `unwrap`/`expect`/`panic!` 残留。若有，改为返回 `EFError`。

**为什么**：DI 工厂 panic 会导致整个服务启动失败，应转为可恢复的 `EFError`。

#### B3. M3.3 错误类型结构化

**文件**：[crates/core/src/error.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/error.rs)（line 5-55）

**修改**（additive，非破坏）：
- 各变体新增可选 `#[source] source: Option<Box<dyn std::error::Error + Send + Sync>>` 字段
- 新增上下文字段（如 `Query` 加 `sql: Option<String>`、`table: Option<String>`）
- impl `std::error::Error::source` 方法
- 保留现有 `From<String>` 构造便利方法，新增 builder 模式 `EFError::query(msg).with_source(e).with_sql(s)`

**为什么**：当前全 String 单字段，丢失原始错误链与上下文，生产排查困难。additive 改造保证向后兼容。

**验证**：`cargo build --workspace --all-features && cargo clippy --workspace --all-features -- -D warnings && cargo test`

### Phase C — M4 P1 性能

#### C1. M4.1 SQLite spawn_blocking

**文件**：[crates/sqlite/src/connection.rs](file:///d:/GitCode/RF/rust-ef/crates/sqlite/src/connection.rs)（line 57-87）

**修改**：`execute`/`query` 内同步 rusqlite 调用包入 `tokio::task::spawn_blocking`，避免阻塞 tokio runtime。

**关键设计**：
- `SqliteConnectionInner::Pooled`：`PooledConnection` 持有 r2d2 连接引用。需验证 `PooledConnection: Send`。若 Send，闭包捕获 `PooledConnection`（owned）+ `sql: String` + `params: Vec<DbValue>`（均 Send）移入 spawn_blocking；若非 Send，在闭包内 `pool.get()`
- `SqliteConnectionInner::Shared`：TokioMutex 已在 async 上下文，无需 spawn_blocking（保持现有 `query_sync` 直接调用）

**为什么**：rusqlite 同步调用阻塞 tokio runtime，高并发下线程饥饿。

#### C2. M4.2 SQLite prepare_cached

**文件**：[crates/sqlite/src/sync_ops.rs](file:///d:/GitCode/RF/rust-ef/crates/sqlite/src/sync_ops.rs)（line 31-33）

**修改**：`conn.prepare(sql)` → `conn.prepare_cached(sql)`

**为什么**：r2d2 连接池复用连接时，per-connection prepared statement cache 生效，避免重复解析 SQL。

#### C3. M4.3 嵌套 include 批量化

**文件**：
- [crates/core/src/navigation_loader.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/navigation_loader.rs)（line 135-140）
- [crates/macros/src/entity.rs](file:///d:/GitCode/RF/rust-ef/crates/macros/src/entity.rs)（nested_loader_arms，line 207-248）

**修改**：`load_nested_includes` 对每个父实体单独调用 `load_includes`（N+1 查询）改为：
1. 收集所有父实体的同层子实体集合
2. 对子实体的导航属性批量 `WHERE id IN (...)` 加载
3. 按父实体分组回填
4. 递归下一层 ThenInclude

宏 `nested_loader_arms` 调整为：收集所有子实体 → 批量 `load_includes` → 回填。

**为什么**：N+1 查询在嵌套 include 场景性能崩塌（100 父 × 10 子 = 1000 查询）。

**风险**：ThenInclude 语义需保持。先实现正确版本（收集同层 → 批量加载 → 回填），性能优化后续迭代。

#### C4. M4.4 批量 UPDATE

**文件**：
- [crates/core/src/change_executor.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/change_executor.rs)（line 102-192）
- [crates/core/src/provider.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/provider.rs)（ISqlGenerator trait，line 588-616）
- 3 provider 的 sql_generator 实现

**修改**：同表 N 个 Modified 实体，当前逐行 UPDATE，改为 CASE WHEN 批量 UPDATE（单 SQL）：

```sql
UPDATE table SET
  col1 = CASE id WHEN ? THEN ? WHEN ? THEN ? END,
  col2 = CASE id WHEN ? THEN ? WHEN ? THEN ? END
WHERE id IN (?, ?, ?)
```

**ISqlGenerator** 加 `update_batch(table, set_cols, pk_col, count) -> (sql_template, param_layout)`。三 provider 实现。

**为什么**：N 次 UPDATE 往返 = N × RTT，批量后 1 次 RTT。

**验证**：`cargo test` + bench 对比（N=10/100/1000 的批量 UPDATE 场景）

**文件**：

- `change_executor.rs::execute_updates`：`set_cols` 用 `modified_properties`（非空时仅 SET 脏列，空时退化为全列）

**为什么**：当前 UPDATE 全列，浪费带宽 + 触发不必要的并发冲突。

**验证**：新增 partial update 测试——修改单列，断言 UPDATE SQL 仅含该列。

#### D2. M5.2 批量 INSERT PK 回填

**文件**：
- [crates/core/src/change_executor.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/change_executor.rs)（line 83-87）
- [crates/core/src/provider.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/provider.rs)（ISqlGenerator）

**修改**：批量 INSERT 后回填真实 PK：
- PostgreSQL：`INSERT ... RETURNING id`，一次查询回填所有
- MySQL：`INSERT ... RETURNING` (MySQL 8.0+) 或逐行 `LAST_INSERT_ID()`
- SQLite：`last_insert_rowid()` + 递增（INTEGER PK 自增时，批量 INSERT 的 rowid 连续）

**ISqlGenerator** 加 `insert_batch_returning(table, cols, count) -> sql`。三 provider 实现。

**为什么**：当前批量 INSERT 后实体 PK 仍为 0，后续 update/delete 失败。

#### D3. M5.3 Upsert API

**文件**：
- [crates/core/src/db_set.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/db_set.rs)（line 25-47）
- [crates/core/src/change_executor.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/change_executor.rs)
- [crates/core/src/provider.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/provider.rs)（ISqlGenerator，line 588-616）
- 3 provider sql_generator 实现

**修改**：
- `db_set.rs`：新增 `upsert(&mut self, entity: T)` —— 标记为 Added + upsert 语义（内部标记 `EntityState::Added` + `is_upsert: bool` flag）
- `change_executor.rs`：`execute_upserts` 用 `INSERT ... ON CONFLICT DO UPDATE`（PG/SQLite）/ `INSERT ... ON DUPLICATE KEY UPDATE`（MySQL）
- `ISqlGenerator`：加 `upsert(table, cols, conflict_cols) -> sql`；三 provider 实现

**为什么**：当前无 upsert，用户需手写 SELECT+INSERT/UPDATE，竞态条件难处理。

**决策**：`EntityState` 不加变体（避免破坏枚举 match）。用 `is_upsert` flag 在 change_executor 内分流。

#### D4. M5.4 Raw SQL → 实体映射

**文件**：[crates/core/src/db_context.rs](file:///d:/GitCode/RF/rust-ef/crates/core/src/db_context.rs)（line 600-602 附近）

**修改**：新增 `DbContext::sql_query<T: IFromRow>(&self, sql: &str, params: &[DbValue]) -> EFResult<Vec<T>>`：

```rust
pub async fn sql_query<T: IFromRow + IEntityType>(&self, sql: &str, params: &[DbValue]) -> EFResult<Vec<T>> {
    let mut conn = self.provider.get_connection().await?;
    let rows = conn.query(sql, params).await?;
    crate::entity::materialize_entities(&rows)
}
```

**为什么**：复杂查询（多表 JOIN、CTE、窗口函数）LINQ 难表达，raw SQL 逃生舱必要。复用 M2 后的 `IFromRow`（已支持 `&[DbValue]`），无需新 trait。

**验证**：新增 raw SQL 测试——`sql_query::<Blog>("SELECT * FROM blogs WHERE id = $1", &[DbValue::I32(1)])`

## Assumptions & Decisions

1. **M2 7.4 + Layer 8 优先**：必须先恢复编译并验证 M2 完整性，再推进 M3-M6。

5. **M3.3 错误结构化是 additive**：新增可选字段，保留现有 `From<String>` 构造便利。非破坏性变更。
6. **每 Phase 结束四项验证**：build + clippy + test + fmt。
