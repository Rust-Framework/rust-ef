# rust-ef 2.2 迁移指南（数据库级约束对齐）

适用对象：

- 从 **rust-ef 2.1.x** 升级到 **2.2** 的应用；
- 需要在 MySQL / PostgreSQL / SQLite code-first DDL 中表达复合唯一约束、部分唯一索引、表达式索引、复合外键、CHECK、列默认值与表选项的应用。

2.2 是增量能力发布：数据操作层（DbContext / LINQ / 变更跟踪 / 事务）与 DI 语义不变，变化集中在**模型元数据与迁移 DDL**。

## 1. 依赖调整

```toml
[dependencies]
rust-ef = "2.2"
rust-ef-sqlite = "2.2"     # 或 rust-ef-postgres / rust-ef-mysql，保持同版本
```

四个 crate 必须同版本；`rust-dix` 仍为 `0.10`，MSRV 仍为 **1.95**。

## 2. 源码兼容性

| 变更 | 影响 | 迁移 |
|------|------|------|
| `EntityTypeMeta` 新增 `indexes` / `foreign_keys` / `checks` / `table_options` | 手写结构体字面量缺字段 | 补 `..EntityTypeMeta::default()`；derive 宏生成的实现无需改动 |
| `SnapshotColumn` 新增 `default_value` | 手写快照字面量缺字段 | 补 `default_value: None` 或 `..Default::default()` |
| `SnapshotEntityType` 新增 `indexes` / `foreign_keys` / `checks` / `table_options` | 同上 | 补 `..Default::default()` |
| `EntityTypeBuilder::has_index(&[...])` 返回 `IndexBuilder<'_, T>`（原 `&mut Self`） | 作为语句调用不受影响；链式 `has_index(...).to_table(...)` 不再成立 | 拆成两条语句 |
| 迁移快照 JSON 由 serde_json 生成（格式化、字段更全） | 旧快照仍可读（缺失字段按默认值处理） | 无需手工迁移；建议重新生成一次快照 |
| `ensure_created` 仍不生成独立索引/外键 | 与 2.1 行为一致 | 需要完整约束时使用 `MigrationEngine::generate` + `apply` |

## 3. 新能力

### 3.1 复合唯一约束 / 多列索引

```rust
#[entity(Order)]
impl IEntityTypeConfiguration<Order> for OrderConfig {
    fn configure(&self, entity: &mut EntityTypeBuilder<'_, Order>) {
        // UNIQUE(tenant_id, request_key)
        entity
            .has_index(&[Order::COLUMN_TENANT_ID, Order::COLUMN_REQUEST_KEY])
            .is_unique();

        // 普通复合索引 + 显式名字
        entity
            .has_index(&[Order::COLUMN_TENANT_ID, Order::COLUMN_STATUS])
            .has_name("ix_orders_tenant_status");
    }
}
```

### 3.2 部分唯一索引与表达式索引

```rust
// PostgreSQL/SQLite: ... WHERE status = 'PENDING'
// MySQL: UNIQUE ((CASE WHEN status = 'PENDING' THEN tenant_id END), ...)
entity
    .has_index(&[Invite::COLUMN_TENANT_ID, Invite::COLUMN_CODE])
    .is_unique()
    .has_filter(linq!(filter |i: Invite| i.status == "PENDING"));

// UNIQUE (coalesce(channel_id, ''))
entity
    .has_index_expression(&["coalesce(channel_id, '')"])
    .is_unique();
```

MySQL 没有部分索引：过滤的 UNIQUE 索引用函数索引模拟；过滤的普通索引只输出 warning 注释（不会生成非法 SQL）。

### 3.3 复合外键与标量外键

```rust
// 标量：#[foreign_key(target)] 现在参与 DDL
#[foreign_key(Customer)]
pub customer_id: i32,

// 复合
entity.has_foreign_key(
    &[Voucher::COLUMN_TENANT_ID, Voucher::COLUMN_ORDER_ID],
    OrderRecord::TABLE,
    &[OrderRecord::COLUMN_TENANT_ID, OrderRecord::COLUMN_ID],
).on_delete(DeleteBehavior::Cascade);
```

SQLite 迁移脚本把外键内联到 `CREATE TABLE`（不支持 `ALTER TABLE ADD CONSTRAINT`）。

### 3.4 CHECK、默认值与表选项

```rust
entity.property_named("amount").has_check("amount > 0").has_default("0");
entity.property_named("version").has_default("1");
entity.has_check("CK_orders_status", "status IN ('PENDING','PAID','CANCELLED')");
entity.engine("InnoDB").charset("utf8mb4").collate("utf8mb4_bin");
```

### 3.5 `Option<T>` 类型映射

`Option<String>` + `#[max_length(n)]` 现在生成 `VARCHAR(n)`（MySQL 可建索引），不再退化为 `TEXT`。

## 4. MySQL 读取缺陷修复

`rust-ef-mysql` 之前先按 `uuid::Uuid` 解码列值；sqlx-mysql 的 UUID 解码接受任意 16 字节，
导致 16 字符 `VARCHAR` 被静默读成 UUID。2.2 改为先按 `String` 解码，UUID 列（`CHAR(36)`）
通过 `TryFrom<DbValue> for Uuid` 还原。若你曾为该项目在应用侧 vendor 补丁，可移除。
