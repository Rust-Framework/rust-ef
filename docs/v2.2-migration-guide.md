# rust-ef 2.2 迁移指南（数据库级约束 + EFCore 实体配置对齐 + 可组合谓词）

适用对象：

- 从 **rust-ef 2.1.x** 升级到 **2.2** 的应用；
- 需要在 MySQL / PostgreSQL / SQLite code-first DDL 中表达复合唯一约束、部分唯一索引、表达式索引、复合外键、CHECK、列默认值与表选项的应用；
- 需要把 `HasColumnType` / `HasPrecision` / `HasComment` / `HasComputedColumnSql` / `UseCollation` / `ToView` / `HasNoKey` / `HasAlternateKey` / `ToTable(schema)` / 枚举转换从业务代码迁回框架配置的应用；
- 需要按请求动态拼装 WHERE 条件的列表/搜索/导出接口（**条件构建 API 有破坏性变更**，见第 3 部分）。

2.2 在模型元数据、迁移 DDL 与条件构建三处有变化；DI 语义与 MSRV 不变。**条件构建部分有破坏性变更**，请逐条对照第 3 部分。EFCore 实体配置对齐（原计划随 2.3 发布）与数据库级约束一起在 2.2.0 发布。

## 1. 依赖调整

```toml
[dependencies]
rust-ef = "2.2"
rust-ef-sqlite = "2.2"     # 或 rust-ef-postgres / rust-ef-mysql，保持同版本
```

四个 crate 必须同版本；`rust-dix` 仍为 `0.10`，MSRV 仍为 **1.95**。

## 2. 源码兼容性

| 变更 | 影响 | 迁移 |
|------|------|------|
| `EntityTypeMeta` 新增 `indexes` / `foreign_keys` / `checks` / `table_options` | 手写结构体字面量缺字段 | 补 `..EntityTypeMeta::default()`；derive 宏生成的实现无需改动 |
| `SnapshotColumn` 新增 `default_value` | 手写快照字面量缺字段 | 补 `default_value: None` 或 `..Default::default()` |
| `SnapshotEntityType` 新增 `indexes` / `foreign_keys` / `checks` / `table_options` | 同上 | 补 `..Default::default()` |
| `EntityTypeBuilder::has_index(&[...])` 返回 `IndexBuilder<'_, T>`（原 `&mut Self`） | 作为语句调用不受影响；链式 `has_index(...).to_table(...)` 不再成立 | 拆成两条语句 |
| 迁移快照 JSON 由 serde_json 生成（格式化、字段更全） | 旧快照仍可读（缺失字段按默认值处理） | 无需手工迁移；建议重新生成一次快照 |
| `ensure_created` 仍不生成独立索引/外键 | 与 2.1 行为一致 | 需要完整约束时使用 `MigrationEngine::generate` + `apply` |

## 3. 新能力

### 3.1 复合唯一约束 / 多列索引

```rust
#[entity(Order)]
impl IEntityTypeConfiguration<Order> for OrderConfig {
    fn configure(&self, entity: &mut EntityTypeBuilder<'_, Order>) {
        // UNIQUE(tenant_id, request_key)
        entity
            .has_index(&[Order::COLUMN_TENANT_ID, Order::COLUMN_REQUEST_KEY])
            .is_unique();

        // 普通复合索引 + 显式名字
        entity
            .has_index(&[Order::COLUMN_TENANT_ID, Order::COLUMN_STATUS])
            .has_name("ix_orders_tenant_status");
    }
}
```

### 3.2 部分唯一索引与表达式索引

```rust
// PostgreSQL/SQLite: ... WHERE status = 'PENDING'
// MySQL: UNIQUE ((CASE WHEN status = 'PENDING' THEN tenant_id END), ...)
entity
    .has_index(&[Invite::COLUMN_TENANT_ID, Invite::COLUMN_CODE])
    .is_unique()
    .has_filter(linq!(filter |i: Invite| i.status == "PENDING"));

// UNIQUE (coalesce(channel_id, ''))
entity
    .has_index_expression(&["coalesce(channel_id, '')"])
    .is_unique();
```

MySQL 没有部分索引：过滤的 UNIQUE 索引用函数索引模拟；过滤的普通索引只输出 warning 注释（不会生成非法 SQL）。

### 3.3 复合外键与标量外键

```rust
// 标量：#[foreign_key(target)] 现在参与 DDL
#[foreign_key(Customer)]
pub customer_id: i32,

// 复合
entity.has_foreign_key(
    &[Voucher::COLUMN_TENANT_ID, Voucher::COLUMN_ORDER_ID],
    OrderRecord::TABLE,
    &[OrderRecord::COLUMN_TENANT_ID, OrderRecord::COLUMN_ID],
).on_delete(DeleteBehavior::Cascade);
```

SQLite 迁移脚本把外键内联到 `CREATE TABLE`（不支持 `ALTER TABLE ADD CONSTRAINT`）。

### 3.4 CHECK、默认值与表选项

```rust
entity.property_named("amount").has_check("amount > 0").has_default("0");
entity.property_named("version").has_default("1");
entity.has_check("CK_orders_status", "status IN ('PENDING','PAID','CANCELLED')");
entity.engine("InnoDB").charset("utf8mb4").collate("utf8mb4_bin");
```

### 3.5 `Option<T>` 类型映射

`Option<String>` + `#[max_length(n)]` 现在生成 `VARCHAR(n)`（MySQL 可建索引），不再退化为 `TEXT`。

## 4. MySQL 读取缺陷修复

`rust-ef-mysql` 之前先按 `uuid::Uuid` 解码列值；sqlx-mysql 的 UUID 解码接受任意 16 字节，
导致 16 字符 `VARCHAR` 被静默读成 UUID。2.2 改为先按 `String` 解码，UUID 列（`CHAR(36)`）
通过 `TryFrom<DbValue> for Uuid` 还原。若你曾为该项目在应用侧 vendor 补丁，可移除。

## 5. 验收清单

- `cargo tree -i rust-dix` 只有一份 `0.10.x`；
- `cargo test -p rust-ef --all-features --test constraints_tests` 通过；
- MySQL 首装 DDL 包含 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`、复合唯一索引、CHECK；
- 重新生成 `model_snapshot.json` 后再做后续差分迁移；
- 条件构建按第 3 部分迁移后，`cargo test -p rust-ef --all-features --test predicate_tests` 与 `--test linq_tests` 通过。

# 第 3 部分：可组合谓词与条件构建（破坏性）

2.1 的 `linq!` 把条件编译成 `QueryBuilder` 方法链；2.2 改为编译成**条件树**（`Predicate<T>`），再由 `filter` 应用。条件能力等价，但写法与部分 API 有意变更。

## 3.1 语法

| 2.1 | 2.2 | 说明 |
|---|---|---|
| `linq!(filter \|b: Blog\| cond)` | `linq!(\|b: Blog\| cond)` | `filter` 关键字删除；裸条件闭包就是谓词形式 |
| `linq!(Blog, \|b\| cond)` | `linq!(\|b: Blog\| cond)` | 未文档化的「类型在前」形式移除 |
| `linq!(\|b: Blog\| cond => b.url)`（无 source） | `linq!(ctx.set::<Blog>(), \|b: Blog\| cond => b.url)` 或 `; order_by b.url` | 排序需要一个查询；带 source 时 `=>` 糖仍可用 |
| `.filter(linq!(filter \|b: Blog\| cond))` | `.filter(linq!(\|b: Blog\| cond))` | `filter` 现在接收谓词，不再接收闭包 |

## 3.2 API 变更

| 2.1 | 2.2 | 迁移 |
|---|---|---|
| `QueryBuilder::filter(FnOnce(QueryBuilder<T>) -> QueryBuilder<T>)` | `filter(impl Into<Predicate<T>>)` | 手写闭包改为谓词（或 `Predicate::from_expr`）；`linq!` 调用方无需改动 |
| `QueryBuilder::where_(p)`（开发期 API，未发布） | `QueryBuilder::filter(p)` | 直接用 `filter` |
| `linq!(filter ...)` → `BoolExpr` | `linq!(|b: T| ...)` → `Predicate<T>` | 需要 `BoolExpr` 时 `.into_expr()` |
| `filter_column` / `filter_in` / `filter_like` / `filter_not_*` / `or_where` | 删除 | 用 `linq!(|b: T| ...)` 或 `BoolExpr::Filter(FilterCondition::with_values(...))` |
| `ModelBuilder::has_query_filter` 接收 `BoolExpr` | 接收 `impl Into<Predicate<T>>`（`T` 可从谓词推断） | 旧的 `linq!(filter ...)` 写法改为 `linq!(|b: T| ...)` |
| `IndexBuilder::has_filter(BoolExpr)` | `has_filter(impl Into<BoolExpr>)` | 同上；`BoolExpr` 仍可直接传入 |

## 3.3 推荐写法

```rust
use rust_ef::prelude::*;

let mut predicate = Predicate::<Blog>::always()
    .and(linq!(|b: Blog| !b.is_deleted))
    .and_opt(keyword.map(|kw| {
        linq!(|b: Blog| b.url.contains(kw))
            .or(linq!(|b: Blog| b.title.contains(kw)))
    }))
    .and_opt(min_rating.map(|r| linq!(|b: Blog| b.rating >= r)));

let query = ctx.set::<Blog>().query().filter(predicate);
let total = query.clone().count().await?;   // count 与列表共用同一份条件
```

- 可选条件用 `and_opt` / `or_opt`；`always()` / `never()` 是恒等起点，不会生成 `1=1` / `1=0`；
- 同一 predicate 可复用于 `count` / 列表 / 导出；
- 空 `IN` 列表现在生成 `1 = 0`（不匹配任何行），不必先判空；
- `!b.flag` 的 SQL 形态变为 `NOT (flag = ?)`（语义不变），依赖 SQL 文本的测试需要同步。

# 第 2 部分：EFCore 实体配置对齐

> 这组能力原计划随 2.3 发布；本次 2.2.0 与数据库级约束一起发布，升级方式与第 1 部分相同。


适用对象：从 **2.1.x** 升级到 **2.2**，或需要把 `HasColumnType` / `HasPrecision` / `HasComment` / `HasComputedColumnSql` / `UseCollation` / `ToView` / `HasNoKey` / `HasAlternateKey` / `ToTable(schema)` / 枚举转换从业务代码迁回框架配置的应用。

### 1. 依赖调整

```toml
[dependencies]
rust-ef = "2.2"
rust-ef-sqlite = "2.2"   # 或 postgres / mysql，保持同版本
```

`rust-dix` 仍为 `0.10`，MSRV 仍为 **1.95**。

### 2. 兼容性

| 变更 | 影响 | 迁移 |
|---|---|---|
| `PropertyMeta` 新增 `column_type` / `precision` / `scale` / `is_fixed_length` / `collation` / `comment` / `computed_sql` / `computed_stored` / `default_value` | 手写 `PropertyMeta` 字面量缺字段 | 补字段或改用 `PropertyMetaBuilder` |
| `EntityTypeMeta` 新增 `is_view` / `is_keyless` / `comment`；移除侧表 `column_defaults` | 同上 | 补 `..EntityTypeMeta::default()`；默认值改用 `property_named(...).has_default(...)` |
| `SnapshotColumn` / `SnapshotEntityType` / `SnapshotIndex` 新增字段 | 手写快照字面量缺字段 | 补 `..Default::default()` |
| 计算列不再出现在 INSERT/UPDATE | 以前手写计算列会被写入 | 现在由数据库生成，符合预期 |

### 3. 新能力速查

#### 3.1 列类型 / 精度 / 定长 / 排序规则 / 注释

```rust
entity.property_named("payload").has_column_type("JSON");
entity.property_named("price").has_precision(12, 2);
entity.property_named("currency").is_fixed_length().has_max_length(3);
entity.property_named("code").has_collation("utf8mb4_bin").has_comment("业务编码");
```

派生属性等价：`#[column_type("JSON")]`、`#[precision(12,2)]`、`#[fixed_length]`、`#[collation("...")]`、`#[comment("...")]`。

#### 3.2 计算列

```rust
entity
    .property_named("total")
    .has_computed_column_sql("unit_price * quantity")
    .is_stored();
// 或派生：#[computed("unit_price * quantity", stored)]
```

计算列自动从 INSERT/UPDATE 排除；SQLite/MySQL 支持，PostgreSQL 必须 STORED。

#### 3.3 表注释 / 视图 / 无键 / schema

```rust
entity.has_comment("订单表");
entity.to_view("v_order_summary");   // 不生成建表 DDL
entity.has_no_key();                 // 无主键
entity.to_schema("shop");            // "shop"."orders"
```

派生等价：`#[table("orders", comment = "...")]`、`#[table("v", view)]`、`#[keyless]`、`#[table("orders", schema = "shop")]`。

#### 3.4 备用键 / INCLUDE

```rust
entity.has_alternate_key(&[Order::COLUMN_TENANT_ID, Order::COLUMN_NO]);
entity.has_index(&[Order::COLUMN_TENANT_ID]).include(&[Order::COLUMN_STATUS]);
```

INCLUDE 仅 PostgreSQL 生效；MySQL/SQLite 输出 warning 并忽略。

#### 3.5 枚举转换 `DbEnum`

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, rust_ef::DbEnum)]
pub enum OrderStatus {
    #[default]
    Pending,
    #[db_value("PAID")]
    Paid,
}
```

枚举字段、`linq!` 过滤和行物化直接可用；需同时 `derive(Default)`。

### 4. 自动升级（下一次迭代加字段）

```rust
// 应用内 snapshot 子命令（CLI 看不到 inventory 模型）
rust_ef::migration::save_registered_snapshot(
    "current_snapshot.json",
    None,
    rust_ef::migration::MigrationDialect::MySql,
)?;
```

```bash
rust-ef migration add AddStock --snapshot current_snapshot.json --dir Migrations --dialect mysql
```

```rust
// 启动时应用（等价 EF Core Database.Migrate()）
let applied = ctx.migrate("Migrations").await?;
```

- PostgreSQL/SQLite 的迁移脚本（含历史行）原子执行，失败回滚；MySQL DDL 隐式提交。
- 新增可空列/带默认值列全自动；无默认值的 NOT NULL 列会输出警告（非空表需回填）。
- SQLite 对既有表增删 FK/CHECK 会输出 warning（需重建表）。
- 完整步骤见 [自动升级流程](rust-ef/09-transactions-migrations/auto-upgrade.md)。

### 5. 验收清单

- `cargo test -p rust-ef --all-features --test entity_config_tests` 通过；
- `cargo test -p rust-ef --all-features --test migration_automation_tests` 通过；
- MySQL/PG 首装 DDL 含 schema 限定、列类型覆盖、注释、计算列；
- 视图实体不出现在 `CREATE TABLE`，`ensure_deleted` 不删除视图；
