# rust-ef 2.1 迁移指南（rust-dix 0.10 / 类型化 key / AnyKey / 异步）

适用对象：

- 从 **rust-ef 2.0.x（rust-dix 0.7）** 升级到 **2.1（rust-dix 0.10）** 的应用；
- 从 2.1 预览版本升级的应用（2.1 已合并 rust-dix 0.8/0.9/0.10 的全部语义与新能力）。

2.1 是“语义 + 能力”合并发布：严格 scope 校验、MEDI 注册语义、类型化 context key、
AnyKey 动态上下文、异步 provider 初始化、MSRV 1.95 与安全基线。

## 1. 依赖调整

```toml
[dependencies]
rust-ef = "2.1"
rust-ef-sqlite = "2.1"     # 或 rust-ef-postgres / rust-ef-mysql，保持同版本
rust-dix = "0.10"
```

- rust-ef 2.1 要求 `rust-dix ^0.10` 与 **Rust 1.95+**；0.7–0.9 的容器类型不兼容，不能混用（0.9→0.10 源码兼容）。
- 应用若直接依赖 `rust-dix`，必须同步到 **0.10**：直接依赖 0.9 会让应用看到的
  `ServiceCollection` 与 rust-ef 的 trait impl 类型不一致，`add_dbcontext*` 方法会不可见。
- 验证只有单一版本：`cargo tree -i rust-dix`。

## 2. 破坏性语义

| 变更 | 2.0.x 行为 | 2.1 行为 | 迁移 |
|------|-----------|---------|------|
| 根 provider 解析 Scoped | 根上 `get::<DbContext>()` 缓存为根级单例 | 默认严格校验，返回 `RdiError::ScopedFromRootProvider` | 共享解析改用 `provider.scope()`；owned 解析仍可从根（`get_owned`/`get_keyed_owned`/`#[inject(owned)]`） |
| 单服务注册顺序 | 实际先注册优先 | **后注册优先**（MEDI） | 同一 key 重复注册时最后一次生效；需要“仅未注册时添加”用 `try_add_*` |
| `get_all` | 含 keyed | 只含非 keyed；keyed 用 `get_all_keyed` | rust-ef 不依赖该行为；业务收集多实现时区分 |
| 释放契约 | 无 Provider 级 dispose | Scope 跟踪 Scoped 并逆序释放；`provider.dispose()` 释放单例；释放后 `ProviderDisposed`/`ScopeDisposed` | 停机时调用 `provider.dispose()` |
| 错误枚举 | 可穷举 | `RdiError` 标记 `#[non_exhaustive]`（新增 `ScopedFromRootProvider`、`ProviderDisposed`、`ScopeDisposed`、`SyncSingletonDependsOnAsyncService`、`AsyncServiceRequiresGetAsync` 等） | 穷举 `match` 补 `_ => ...` |
| keyed API | `&str` | typed key（enum → `ServiceKey::new`）+ `impl Into<ServiceKey>`；EF 注册/解析要求 `IDbContextKey + Into<ServiceKey>` | 字符串 key 源码兼容（仍为 `String` key）；typed key 与 string key 不互通 |
| MSRV | 1.94 | **1.95** | 升级工具链 |

### 迁移期逃生门

```rust
use rust_ef::di::{ServiceCollection, ServiceProviderOptions};

let provider = ServiceCollection::new()
    .add_dbcontext(|options| options.use_sqlite("app.db"))
    .build_with(ServiceProviderOptions::lenient())?;
```

`lenient()` 仅用于过渡（恢复 0.7 的根 scope 缓存行为），长期请改为 `provider.scope()` + `get_owned()`。

### rust-dix 0.9 → 0.10 补充

- **源码兼容**：字符串 key、`.await` 与现有 EF 代码无需修改。
- **宏 key 表达式**：`#[inject(key = <expr>)]` / `#[inject(owned, key = <expr>)]` 接受
  `impl Into<ServiceKey>`；表达式按消费者字段构造时求值一次（singleton 在 build/validation
  一次、transient 每次解析一次），应保持稳定且无副作用。
- **扩展契约**：下游应实现 `From<LocalKey> for ServiceKey`（EF 的 `#[derive(DbContextKey)]`
  已生成），不要复制 rust-dix 注入宏。
- `rdi-E004` 编译期重复 key 检测仅对字符串字面量 key 生效；EF 的运行时注册仍是 last-wins。
- `async_any_*` 仍未提供；EF 的 AnyKey 保持同步初始化。

## 3. 新能力（可选，均为增量）

### 3.1 类型化 context key（含 Handler 注入）

用 `#[derive(DbContextKey)]` 生成 `IDbContextKey`（实体模型字符串名）与 rust-dix 0.10
官方扩展契约 `From<Key> for ServiceKey`（typed key），注册、解析和 Handler 注入共享同一个
typed key：

```rust
use rust_ef::db_context::DbContext;
use rust_ef::di::DbContextResolver;
use rust_ef::prelude::*;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, DbContextKey)]
enum Db { Read, Write }

let provider = ServiceCollection::new()
    .add_dbcontext_keyed(Db::Read, |o| { o.use_default_entity_model(); o.use_sqlite("read.db"); })
    .add_dbcontext_keyed(Db::Write, |o| { o.use_default_entity_model(); o.use_sqlite("write.db"); })
    .build()?;

let mut write = provider.get_owned_context(Db::Write)?;   // owned，根上可用
let scope = provider.scope();
let read = scope.get_context(Db::Read)?;                  // shared，需 scope

// rust-dix 0.10 宏 key 表达式：
#[inject(scoped)]
struct WriteHandler {
    #[inject(owned, key = Db::Write)]
    ctx: DbContext,
}
```

约束：

- enum 需派生 `Debug + Clone + Copy + PartialEq + Eq + Hash`（`ServiceKey::new` 的要求）；
- 键名默认是 variant 的 snake_case，可用 `#[key("custom")]` 覆盖；
- 手工实现 `IDbContextKey` 时，必须同时实现 `From<Key> for ServiceKey`（官方扩展契约），
  或改用派生宏；不要复制 rust-dix 的注入宏；
- 字符串 key（`"read"`）仍注册为 `String` key，与 typed enum key 不互通。

### 3.2 AnyKey 动态上下文（租户/分片）

```rust
let provider = ServiceCollection::new()
    .add_dbcontext_anykey(|key, options| {
        let tenant = key.to_string();                 // 先经白名单/租户表校验
        options.use_postgres(tenant_connection_string(&tenant));
    })
    .build()?;

let scope = provider.scope();
let mut ctx = scope.get_keyed_owned::<DbContext>("tenant-a")?;
```

- 一个兜底注册服务任意请求 key；精确 key 注册优先。
- options/provider **按请求 key 缓存**（有界 LRU，默认 256；`add_dbcontext_anykey_with_capacity`
  可调），跨 scope 复用连接池。
- AnyKey 上下文强制使用默认实体模型；租户隔离由查询过滤器负责。
- **安全**：请求 key 必须经白名单/租户表映射，禁止直接拼入 SQL/连接串。
- **注意**：key 基数应受控（LRU 会淘汰最久未用的 key 缓存）；异步 AnyKey 尚未提供。

### 3.3 异步 provider 初始化

```rust
let provider = ServiceCollection::new()
    .add_dbcontext_async(|options| {
        options.use_postgres("postgres://app/db");
        // 可选：连接池创建后的异步自检（失败中止启动）
        options.async_preflight(|options| {
            Box::pin(async move {
                let provider = options.create_provider()?;
                let mut conn = provider.get_connection().await?;
                conn.query("SELECT 1", &[]).await?;
                Ok(())
            })
        });
    })
    .build_async()
    .await?;

// DbContext 仍是同步 Scoped 服务，Handler 的 owned 注入不变
let mut ctx: DbContext = provider.get_owned()?;
```

- provider 创建（连接池）在 `build_async` 中执行；失败返回类型化 `RdiError`，不再在注册期 panic。
- 同步 `build()` 遇到异步注册返回 `RdiError::AsyncServiceRequiresBuildAsync`。
- keyed 变体：`add_dbcontext_keyed_async(key, configure)`。

## 4. 升级检查清单

- [ ] `cargo tree -i rust-dix` 只有 0.10.x；Rust ≥ 1.95
- [ ] 根上 `provider.get::<DbContext>()` / `get_keyed()` 改为 `scope.get*` 或 owned 解析
- [ ] 穷举 `RdiError` 的 `match` 补通配分支
- [ ] 停机流程调用 `provider.dispose()`
- [ ] 使用 `ServiceKey` 直接解析 EF context 时注意 `ServiceKey::new("x")`（`&str` 类型）
      与字符串注册的 `String` key 不相等
- [ ] 如使用 typed key：优先 `#[derive(DbContextKey)]`；手工 key 需同时实现
      `From<Key> for ServiceKey`，且 `IDbContextKey::name()` 与 `#[context("...")]` 一致
- [ ] 如使用 typed key 的 Handler 注入：`#[inject(owned, key = Key::Variant)]`（0.10 宏表达式）
- [ ] 如使用 AnyKey：完成 key 白名单映射、租户隔离过滤器与 key 基数约束
- [ ] 如使用异步注册：应用启动改为 `build_async().await` 并处理 `RdiError`
- [ ] 依赖 rust-webx 的应用升级到支持 rust-dix 0.10 的版本后重新运行测试

## 5. 回滚

锁回 `rust-ef = "2.0"` + `rust-dix = "0.7"`（注意与 2.1 的容器类型不兼容）。
