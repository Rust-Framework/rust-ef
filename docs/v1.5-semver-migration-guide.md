# v1.5 SemVer 严格化迁移指南

> 版本：v1.5.0 — 2026-07-08
> 适用范围：rust-ef workspace 全部 crate（core / sqlite / postgres / mysql / macros / cli）
> 目标：从 v1.5.0 起严格遵循 [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html)，minor 版本不再含 breaking change

---

## 1. 背景：v1.0–v1.4 的 SemVer 偏离

rust-ef 在 v1.0 GA 后的迭代中，多个 minor 版本包含 breaking change。这些变更虽然都在
CHANGELOG 中记录了迁移路径，但违反了 SemVer 2.0.0 的严格解读（minor 版本应保持向后兼容）。
下表汇总历史 breaking change：

| 版本 | breaking change | 迁移路径 |
|------|-----------------|----------|
| v1.1.0 | `#[entity_config(T)]` 重命名为 `#[entity(T)]`，无 deprecated 别名 | 全局替换属性名；`rust_ef::entity_config` → `rust_ef::entity` |
| v1.3.0 | `DbContext::begin_transaction(&self) -> EFResult<Box<dyn IAsyncConnection>>` 改为 `begin_transaction(&mut self) -> EFResult<()>` | 删除返回值绑定；改用 `ctx.commit_transaction()` / `ctx.rollback_transaction()` |
| v1.3.1 | rust-dicore → rust-dix 0.6 重命名 + API 变更：`ServiceCollection::build()` 返回 `Arc<ServiceProvider>`；`get()` / `get_owned()` / `get_keyed_owned()` 返回 `Result` | 移除手动 `Arc::new()` 包装；解析调用加 `.unwrap()` / `?` |
| v1.4.0 | `DbContext.context_key` 字段移除（被 `discover_entities()` no-op 孤立化） | 无外部影响（内部字段）；`from_options()` 自动从 `DbContextOptions` 读取 key |

**根本原因**：v1.x 阶段框架仍在快速演进，API 形态尚未完全收敛。为避免 deprecated 代码
堆积增加维护负担，选择了"干净利索移除"而非"预留过渡期"的策略。

---

## 2. v1.5 SemVer 严格化策略

从 v1.5.0 起，rust-ef 采用以下 SemVer 严格化规则：

### 2.1 版本号约定

- **Patch（x.x.PATCH）**：bug 修复、性能优化、文档更新。不新增公开 API，不移除/重命名
  任何公开项。零 breaking change。
- **Minor（x.MINOR.0）**：新增功能、新增公开 API、扩展 trait 默认方法。**不含 breaking
  change**。需要移除的旧 API 必须在此版本标记 `#[deprecated]`，并在下一个 minor 移除。
- **Major（MAJOR.0.0）**：breaking change 落地。移除上一 minor 已标记 `#[deprecated]`
  的 API。仅在积累足够多 deprecated 项或进行架构级重构时发布。

### 2.2 Deprecation 期规则（1 minor 过渡）

任何需要在 minor 版本移除的公开 API，必须经历 **1 个 minor 版本的 deprecation 期**：

1. **vN.x.0**（标记期）：API 保留但标记 `#[deprecated]`，编译期产生警告，引导用户迁移
2. **vN.(x+1).0**（移除期）：API 物理移除，CHANGELOG 标注 `BREAKING`

```rust
// v1.6.0 — 标记 deprecated
#[deprecated(
    since = "1.6.0",
    note = "use `DbContextOptionsBuilder::slow_query_threshold` instead; this method will be removed in 1.7.0"
)]
pub fn set_slow_query_threshold_deprecated(&mut self, ms: u64) -> &mut Self {
    self.slow_query_threshold(std::time::Duration::from_millis(ms))
}

// v1.7.0 — 物理移除（上述方法删除，CHANGELOG 标注 BREAKING）
```

### 2.3 CHANGELOG 标注规范

- breaking change 必须在 CHANGELOG 条目中用 `### Breaking —` 前缀显式标注
- deprecated 项用 `### Deprecated —` 前缀标注，并注明计划移除版本
- 新增 API 用 `### Added —` 前缀

## 3. 当前 breaking change 清单与迁移路径

以下按版本顺序列出 v1.0–v1.5 的全部 breaking change 及其迁移方式。v1.5.0 本身**不含
breaking change**——tracing 集成通过可选 feature + cfg-gated 默认方法实现，MySQL TLS
通过新增 API（非替换）实现。

### 3.1 v1.1.0 — `#[entity_config(T)]` → `#[entity(T)]`

```rust
// Before (v1.0):
#[entity_config(User)]
struct UserConfig: IEntityTypeConfiguration<User> { ... }

// After (v1.1+):
#[entity(User)]
struct UserConfig: IEntityTypeConfiguration<User> { ... }
```

迁移：全局替换 `entity_config` → `entity`（含 `use rust_ef::entity_config` → `use rust_ef::entity`）。

### 3.2 v1.3.0 — `begin_transaction` 签名变更

```rust
// Before (v1.2):
let conn = ctx.begin_transaction().await?;
// ... operations on conn ...
ctx.save_changes().await?;  // 无法复用 conn（PG/MySQL 池化连接）
conn.commit().await?;

// After (v1.3+):
ctx.begin_transaction().await?;  // 无返回值，事务存储在 DbContext 内
// ... operations via ctx ...
ctx.save_changes().await?;  // 自动复用事务连接
ctx.commit_transaction().await?;
```

迁移：删除返回值绑定；用 `ctx.commit_transaction()` / `ctx.rollback_transaction()` 替代
`conn.commit()` / `conn.rollback()`。

### 3.3 v1.3.1 — rust-dix 0.6 API 变更

```rust
// Before (rust-dicore 0.5.1):
let provider = Arc::new(
    ServiceCollection::new().add_dbcontext(...).build().unwrap()
);
let ctx: DbContext = provider.get_owned();
let ctx: Arc<DbContext> = scope.get();

// After (rust-dix 0.6):
let provider: Arc<ServiceProvider> =
    ServiceCollection::new().add_dbcontext(...).build().unwrap();
let ctx: DbContext = provider.get_owned()?;
let ctx: Arc<DbContext> = scope.get()?;
```

迁移：移除 `Arc::new()` 包装；解析调用加 `?` 或 `.unwrap()`。

### 3.4 v1.4.0 — `DbContext.context_key` 字段移除

内部字段移除，无外部 API 影响。`from_options()` 自动从 `DbContextOptions` 读取
`context_key`。

## 4. `#[deprecated]` 使用规范

从 v1.5 起，任何计划移除的公开 API 必须按以下规范标记：

### 4.1 基本用法

```rust
#[deprecated(
    since = "1.6.0",
    note = "use `new_method_name` instead; this will be removed in 1.7.0"
)]
pub fn old_method_name(&self) -> EFResult<()> {
    // 保留实现，委托到新方法（确保行为一致）
    self.new_method_name()
}
```

### 4.2 trait 方法

trait 方法无法直接 `#[deprecated]`（会污染所有实现者）。替代方案：

```rust
pub trait IAsyncConnection: Send + Sync {
    /// 新方法（v1.6+）。
    fn new_feature(&mut self) -> EFResult<()> { /* default impl */ }

    /// 旧方法，委托到新方法并标记 deprecated。
    #[deprecated(since = "1.6.0", note = "use `new_feature` instead")]
    fn old_feature(&mut self) -> EFResult<()> {
        self.new_feature()
    }
}
```

### 4.3 编译期警告示例

用户代码调用 deprecated API 时，编译器产生警告：

```
warning: use of deprecated method `old_method_name`: use `new_method_name` instead; this will be removed in 1.7.0
  --> src/handlers/user.rs:42:10
   |
42 |     ctx.old_method_name().await?;
   |          ^^^^^^^^^^^^^^^
```

## 5. v1.5.0 新增 API 清单（非 breaking）

v1.5.0 全部为新增 API，通过可选 feature 或 trait 默认方法实现，**不破坏任何现有代码**：

| 新增项 | 类型 | 兼容性机制 |
|--------|------|------------|
| `tracing` 可选 feature | Cargo feature | 默认关闭，零运行时开销 |
| `QueryGuard` / `PoolAcquireGuard` / `SaveChangesGuard` | 新增类型 | observability 模块新增 |
| `DbContextOptionsBuilder::slow_query_threshold()` | 新增方法 | builder 链式 API 扩展 |
| `IAsyncConnection::set_slow_query_threshold()` | trait 默认方法 | cfg-gated，默认空实现 |
| `IDatabaseProvider::set_slow_query_threshold()` | trait 默认方法 | cfg-gated，默认空实现 |
| `MySqlTlsMode` 枚举 | 新增类型 | 独立枚举，不影响现有 `MySqlProvider::new()` |
| `MySqlProvider::new_with_tls()` / `new_lazy_with_tls()` | 新增构造器 | 新增方法，非替换 |
| `DbContextOptionsBuilderExt::use_mysql_with_tls()` | 新增 trait 方法 | 新增方法，非替换 |

## 6. v2.0 候选项

以下变更计划在 v2.0 落地，v1.6–v1.x 会逐步标记 deprecated：

| 候选项 | 原因 | v1.x deprecated 计划 |
|--------|------|---------------------|
| `Arc<EntityTypeMeta>` 共享元数据 | 当前 `EntityTypeMeta` per-DbContext 克隆，Arc 化减少复制 | v1.6 标记相关构造器 deprecated，v2.0 移除 |
| `async trait` 原生语法迁移 | Rust 1.75+ 原生 async trait 稳定后，移除 `async-trait` 依赖 | v1.7 标记 `#[async_trait]` 为可选，v2.0 移除 |
| `EFError` 错误码体系 | 当前错误为枚举变体，无数字错误码；v2.0 引入 `EFErrorCode` | v1.6 新增错误码字段（非 breaking），v2.0 将变体重组 |
| `metrics` API 集成 | v1.5 仅 tracing 事件，v2.0 引入 `metrics::Counter` / `Histogram` | v1.7 新增 metrics feature，v2.0 稳定 |

## 7. 用户迁移检查清单

从 v1.4.x 升级到 v1.5.0 时，**无需修改任何代码**。可选步骤：

- [ ] 如需可观测性：在 `Cargo.toml` 启用 `tracing` feature（`rust-ef = { version = "1.5", features = ["tracing"] }`）
- [ ] 如需慢查询监控：在 `DbContextOptionsBuilder` 调用 `.slow_query_threshold(Duration::from_millis(500))`
- [ ] 如需 MySQL TLS：将 `use_mysql(cs)` 替换为 `use_mysql_with_tls(cs, MySqlTlsMode::Required)`
- [ ] 在应用入口初始化 `tracing_subscriber`（REF 只发事件，不初始化 subscriber）

## 8. v1.6.0 破坏性变更（2026-07-09）

> v1.6.0 是生产硬化迭代，用户已确认接受破坏性变更以换取生产就绪性。以下变更需
> 修改代码才能升级。

### 8.1 `IFromRow::from_row` 签名变更

**变更**：`fn from_row(values: &[String])` → `fn from_row(values: &[DbValue])`

**原因**：消除全链路 String 物化，保留数据库原始类型（i32, f64, bool 等）。

**迁移**：

```rust
// v1.5（旧）
fn from_row(values: &[String]) -> EFResult<Self> {
    Ok(Self { id: values[0].parse()?, name: values[1].clone() })
}

// v1.6（新）
fn from_row(values: &[DbValue]) -> EFResult<Self> {
    Ok(Self {
        id: values[0].clone().try_into()?,
        name: values[0].clone().try_into()?,
    })
}
```

`#[derive(EntityType)]` 自动生成的实现已更新，使用宏的用户无需修改。

### 8.2 `ParseFromDb` trait 移除

**变更**：移除 `ParseFromDb` trait，改用标准 `TryFrom<DbValue>`。

**迁移**：将 `impl ParseFromDb for MyType` 替换为 `impl TryFrom<DbValue> for MyType`。

### 8.3 TLS 默认值变更

**变更**：
- PostgreSQL: `PgTlsMode::Disable` → `PgTlsMode::Require`（默认）
- MySQL: `MySqlTlsMode::Disabled` → `MySqlTlsMode::Required`（默认）

**迁移**：如需明文连接（如本地开发），显式传入 `Disable`/`Disabled`：

```rust
// v1.6 明文连接（逃生舱）
options.use_postgres_with_tls(cs, PgTlsMode::Disable);
options.use_mysql_with_tls(cs, MySqlTlsMode::Disabled);
```

### 8.4 `BoolExpr::raw` 收窄

**变更**：`BoolExpr::raw()` 从 `pub` 收窄为 `pub(crate)`。

**迁移**：用参数化查询替代 raw SQL 片段。如确需 raw SQL，用
`DbContext::sql_query()`（D4 新增）。

### 8.5 `save_changes` 后保留实体

**变更**：`save_changes` 后 Added/Modified → Unchanged（带刷新快照），Deleted 移除。
先前行为是 `clear_entries()`（全部丢弃）。

**影响**：已保存实体保留在 tracker 中，可读取回填的主键。依赖 clear 行为的代码
需手动调用 `db_set.clear_entries()`。

### 8.6 `DbValue` 新增 `TryFrom`（非破坏性）

新增 `TryFrom<DbValue>` for `i8` / `u32` / `u64`。这是 additive 变更，不影响现有代码。

### 8.7 v1.5 → v1.6 迁移检查清单

- [ ] 自定义 `IFromRow` 实现：将 `&[String]` 改为 `&[DbValue]`，用 `TryFrom` 转换
- [ ] 使用 `ParseFromDb` 的代码：迁移到 `TryFrom<DbValue>`
- [ ] 依赖 TLS `Disable`/`Disabled` 默认值的连接：显式传入 `*_with_tls(Disable)`
- [ ] 使用 `BoolExpr::raw` 的代码：迁移到参数化查询或 `sql_query`
- [ ] 依赖 `save_changes` 后 tracker 被清空的代码：手动调用 `clear_entries()`
- [ ] 如需 Upsert：用 `db_set.upsert(entity)` 替代手写 SELECT+INSERT/UPDATE
- [ ] 如需 Raw SQL：用 `ctx.sql_query::<T>(sql, params)` 替代手写查询
