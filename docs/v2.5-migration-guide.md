# rust-ef 2.5.x 迁移指南（2.5.1）

> 基线：2.4.0 → 2.5.0（minor；以修复上游真库缺陷为主，含少量新 API）。
> 输入：Travel `docs/04-development/20-upstream-defects-2026-11-14.md` 的真库复验记录。
> 逐条完整说明见仓库根 [CHANGELOG.md](../CHANGELOG.md)；运行时升级流程见
> [自动升级流程](rust-ef/09-transactions-migrations/auto-upgrade.md)。
>
> **2.5.1 补丁**：修正 PostgreSQL 整数/浮点精度与 `TEXT + max_length` 导致的运行期 diff
> 伪 `ALTER`（真库校验发现）；其余内容与 2.5.0 相同。

## 1. 一句话结论

2.5.0 让「正确使用框架」的 MySQL/PostgreSQL 真库路径不再需要旅行者的本地规避：
PostgreSQL 任意可空类型可写 `NULL`，MySQL 枚举/表达式索引/超长索引名可直接建，网络库
`bootstrap → introspect → diff` 为空，驱动错误保留 SQLSTATE/SQL，连接串与 TLS 构造语义统一。

## 2. 缺陷修复速览

| ID | 级别 | 2.5.0 行为 |
|---|---|---|
| EF-PG-01 | P0 | `DbValue::Null` 使用无类型 NULL 绑定（`IsNull::Yes`），可写入 `BIGINT/NUMERIC/BOOLEAN/DATE/TIMESTAMP/UUID/BYTEA` 等任意可空列；不再报 `error serializing parameter N` |
| EF-MYSQL-01 | P1 | 自定义枚举 + `max_length(n)` 在 MySQL 生成 `VARCHAR(n)`（`fixed_length` 为 `CHAR(n)`），可建普通/复合索引；PG/SQLite 保持 `TEXT` |
| EF-MYSQL-02 | P1 | `has_index_expression` 中裸标识符按列、含函数/运算符的按表达式；混合索引输出 `` (`tenant_id`, ..., (coalesce(...))) ``，不再包出 `(tenant_id)`（MySQL 3762） |
| EF-DDL-01 | P1 | 自动索引/外键名统一按 63 字节可移植上限截断 + 稳定哈希；显式 `has_name` 优先；PG/MySQL 行为一致 |
| EF-DIFF-01 | P1 | MySQL 内省改用 `COLUMN_TYPE` 全拼写并读取函数索引 `EXPRESSION`；列类型/默认值/CHECK/表达式索引比较按方言归一化；网络方言不再生成 `DROP CHECK`；`bootstrap` 后 `introspect + diff` 无语句 |
| EF-DIFF-02 | P2 | `MigrationDiff::has_drift()` / `summary()` / `drift_tables()` 提供只读 drift 信号，可接 `/health/ready` 或指标，不执行 DDL |
| EF-ERR-01 | P2 | 新增 `EFError::Database(DatabaseErrorInfo, ...)`：保留 SQLSTATE、厂商码、message/detail/hint、table/column/constraint 与失败 SQL（截断 512 字符）；`Display` 不再只剩 `db error` |
| EF-CONN-01 | P2 | `ConnectionString::parse_ado` / `parse_auto` 支持 `source/server/host`、`uid/pwd`、`database/initial catalog`、别名、引号值、尾随/重复分号、`ssl-mode` |
| EF-DDL-02 | P2 | `CheckExpr` 可移植 CHECK 构造器；`MigrationEngine::validate_check_expression` 在生成期标记已知方言陷阱 |
| EF-PG-02 | P2 | `use_postgres`/`PostgresProvider::new` 与 MySQL 一致：默认要求 TLS，URL 显式 `sslmode=disable`/`ssl-mode=disabled` 才明文；`verify-*` 不再被驱动拒绝 |
| 包 E | 工程化 | `rust-ef migration ddl --snapshot ...`（三方言 dry-run，不连库）、`migration capabilities`、provider capability matrix、CI 真库作业 |

## 3. 兼容点（升级前检查）

1. **`EFError` 新增 `Database` 变体**：`EFError` 不是 `#[non_exhaustive]`，下游穷举 `match` 需补一个分支
   （推荐 `_ => ...`）。已匹配 `UniqueViolation` 的代码不受影响。
2. **MySQL 自动名可能变化**：超过 63 字节的自动索引名现在截断 + 哈希（此前 64 字符上限且哈希位数可能溢出）；
   显式 `has_name` 不受影响。已按旧名建库的对象会被视为“库里多出的索引”只报 `skipped_removal` info，
   不会 DROP；需要严格对齐时在模型显式 `has_name` 同名，或写版本化迁移改名。
3. **MySQL 内省的 `DbColumn::data_type` 变为 `COLUMN_TYPE` 全拼写**（`varchar(64)`、`tinyint(1)`、
   `decimal(10,2)`、`datetime(6)`）。直接读取 `data_type` 做类型分派的代码需按包含关系匹配
   （scaffold 已按此实现）；只读展示/日志不受影响。
4. **网络方言的运行时 diff 不再 DROP CHECK**：同名但服务器规范化表达式不同的 CHECK 现在只报
   `constraint_not_introspected` info。需要修改 CHECK 时写版本化迁移（这是有意的加法安全策略）。
5. **`MySqlTlsMode` 新增 `Preferred` 变体**（对应 URL `ssl-mode=preferred`）；默认构造仍是 `Required`。
   穷举 `match MySqlTlsMode` 的代码需补分支。
6. **可移除的旅行者规避**（应用侧，非框架 API 破坏）：
   - `code_first_model_for` 中“枚举 TEXT → VARCHAR(n)”补丁；
   - 混合表达式索引折叠成 `cast(concat_ws(...))` 的补丁；
   - 为超长自动索引名显式加 `has_name` 的补丁；
   - 启动器对 MySQL/PG 直接跳过运行期 diff 的策略（可改为“diff + 只读 drift 健康检查”）。

## 4. 迁移步骤

```toml
# Cargo.toml
rust-ef = { version = "2.5", features = ["webx"] }
rust-ef-postgres = "2.5"   # 或 rust-ef-mysql / rust-ef-sqlite
```

1. `cargo update -p rust-ef --precise 2.5.0`（三个 provider 同步到 2.5.0）。
2. 下游穷举 `match EFError` / `match MySqlTlsMode` 补分支（见 §3）。
3. 删除 §3.6 的本地规避，跑一次安装/升级自检：
   ```rust
   let model = ctx.model_builder().build();
   let live = provider.introspect().await?;
   let diff = engine.diff_metas(&model, &live);
   assert!(diff.is_empty(), "fresh bootstrap must diff to no statements:\n{}", diff.report());
   ```
4. 若使用 SecretFile 之外的网络库：确认连接串 TLS 参数（`sslmode=disable` / `ssl-mode=disabled`）
   与部署环境一致；不要依赖“隐式明文”。
5. 把 `diff.has_drift()` 接入 `/health/ready`（只读，不自动 DDL）。

## 5. 验证基线（本仓库）

```powershell
cd server            # rust-ef 仓库根
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check

# MySQL / PostgreSQL 真库（可选 CI job）
$env:RUST_EF_MYSQL_URL = 'mysql://root:root@127.0.0.1:3306/ef_ci?ssl-mode=disabled'
$env:RUST_EF_PG_URL = 'postgres://postgres:postgres@127.0.0.1:5432/ef_ci?sslmode=disable'
cargo test -p rust-ef --test provider_parity_tests -- --ignored --nocapture
cargo test -p rust-ef --test postgres_null_binding -- --ignored --nocapture
```

验收重点：

- `postgres_null_binding`：同一实体模型上 `None` 的 INSERT/UPDATE/读回全部成功；`Some` 对照通过。
- MySQL：枚举列建普通/复合索引成功；混合表达式唯一索引能阻止重复；任意长自动索引名可创建。
- 网络库：`bootstrap` 后立即 `introspect + diff_metas` 无 statements（仅可能有 info 级表达式索引提示）。
- 失败 SQL：日志/`Display` 含 SQLSTATE、表/列/约束与 SQL 片段，客户端仍只看到固定 5xx 文案。
