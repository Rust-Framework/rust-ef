# rust-ef 2.9 迁移指南：报表查询与集合写对象化

> 适用：`2.6.x → 2.9.0`（minor，纯加法为主）。本版本与 **rust-webx 2.9.0**
> 配对发布（rust-xazgo 服务栈要求两 crate 同步升级）。
> 逐条完整说明见仓库根 [CHANGELOG.md](../CHANGELOG.md)；
> 新 API 的用法见 [类型化投影与报表行](rust-ef/06-advanced-query/typed-projections.md)
> 与 [GROUP BY 与 HAVING](rust-ef/06-advanced-query/group-by-having.md)。

## 1. 一句话结论

2.9.0 把「分组聚合报表、整数/Decimal 精确聚合、复合/链式 JOIN、`col = col + 1`
更新、任意结果行物化」从原生 SQL 搬回对象 API。已有代码**不需要改**；
只有直接构造 `JoinSpec`/`QueryState`、读取 `QueryState::parameters`/`params()`
（已删除）、调用 `QueryBuilder::compile_sql`（现返回 `EFResult`）或只读
`ExecuteUpdateBuilder::params()`（现返回 `EFResult`）、穷举
`match BoolExpr`/`HavingExpr`、使用已废弃的
`set_column_internal`、或依赖旧 `IFromRow: IEntityType` supertrait bound 的极少
数代码需要按 §3 调整。

## 2. 新能力速查（不改旧代码）

| 需求 | 2.9.0 写法 |
|---|---|
| 分组报表：组键 + 聚合 + 别名 + 排序 + 限量 | `ctx.set::<Order>().query().filter(pred).group_by(&[Order::COLUMN_CURRENCY]).select_items(&[SelectItem::column(Order::COLUMN_CURRENCY), SelectItem::sum(Order::COLUMN_TOTAL).alias("total")]).order_by_desc_raw("total").take(20).to_list_rows::<RevenueRow>().await?` |
| `linq!` 里写分组聚合 | `linq!(ctx.set::<Order>(), \|o: Order\| o.tenant_id == t; group_by o.currency; select (o.currency, sum(o.total_amount), count()))` 返回 `SelectQueryBuilder`，再 `.to_list_typed_3::<String, i64, i64>().await?` |
| 整数/Decimal 精确求和 | `let total: i64 = linq!(ctx.set::<Order>(); sum_i64 o.total_amount).await?;` 或 `sum_as::<i64>(col)` / `avg_as::<f64>(col)` |
| 报表行（非实体） | `#[derive(FromRow)] struct RevenueRow { currency: String, total: i64 }` + `to_list_rows::<RevenueRow>()` / `ctx.sql_query_rows::<RevenueRow>(sql, params)` |
| 复合键 JOIN | `linq!(...; inner_join \|o: Order, s: Shipment\| o.id == s.order_id && o.region_id == s.region_id)`；运行时 `query().join::<Shipment>(JoinKind::Inner, &[("id", "order_id"), ("region_id", "region_id")])` |
| 链式 JOIN | 连续多个 join 子句（`inner_join \|s: Shipment, n: Note\| ...`），或运行时 `join_from::<Note, Shipment>(JoinKind::Inner, &[...])` |
| 过滤被 join 表 | `query().filter_joined::<Shipment>(linq!(\|s: Shipment\| s.carrier == "UPS"))`（自动限定为 `shipments.carrier`） |
| `col = col + 1` / 扣减库存 | `execute_update().increment(Order::COLUMN_VERSION, 1)` / `.decrement(Order::COLUMN_STOCK, qty)` / `.set_column_expr(Order::COLUMN_TOTAL, ColumnExpr::column(Order::COLUMN_TOTAL).add(ColumnExpr::column(Order::COLUMN_DISCOUNT)))` |
| `linq!` 表达式更新 | `linq!(...; set o.version, o.version + 1; execute_update)` |

## 3. 破坏性/可观测边界变化

> 本节十项是**源码级破坏**（仅影响直接构造这几个公开类型、穷举 `match`
> `BoolExpr`/`HavingExpr`、调用这些已改签名的入口、使用已废弃别名、或依赖旧
> `IFromRow: IEntityType` bound 的代码）；builder API 其余部分全部为加法。第 1-6、9、
> 10 项（类型/枚举形状与 CTE 引号）在 workspace 的
> `[workspace.metadata.cargo-semver-checks.lints]` 中按本文档/CHANGELOG 登记为 2.9
> 允许项；第 7、8 项是返回类型改为 `EFResult`（调用点补 `?`），属于 semver 可见的
> 源码破坏，按本文档与 CHANGELOG 记录。

1. **`JoinSpec`**：`{ join_type: String, table: String, on_clause: String }`
   → `{ kind: JoinKind, table: String, keys: Vec<JoinKey> }`，并标记
   `#[non_exhaustive]`。框架内部与 `linq!` 已全部改走 builder；直接构造
   `JoinSpec` 的三方代码改为新增的 `JoinSpec::new(kind, table, keys)`、
   `QueryBuilder::{join, join_from}`，或 `JoinKey { left_table, left_column, right_column }`。
   旧 `inner_join_internal` / `left_join_internal` / ... 仍保留，生成 SQL 逐字符不变。
2. **`QueryState`**：SELECT 形态收敛为单一 `SelectList` 枚举（公开类型；`QueryState`
   上的字段私有），
   新增 `validation_error` / `from_changed_after_join` 两个私有不变量字段，并标记
   `#[non_exhaustive]`。→ 不再能结构体字面量构造，统一改用
   `QueryState::new(table)`；被移除的公开字段改由同名访问器读取：
   `projected_columns()`、`is_count()`、`is_exists()`、`aggregate()`；类型化投影用
   `projections()` 读取（经 `select_items`/`group_by` 等 builder 构造）。
   框架终端的 SQL 与行为不变。

3. **`QueryState::parameters` 字段与 `QueryState::params()` 方法已移除**：
   2.6 的 `pub parameters: Vec<DbValue>` 字段与 `params()` 访问器在 2.9 删除（2.6
   的 `params()` 返回「注册子句时累积」的 WHERE+HAVING 混合参数）。参数不再作为可
   单独读取的状态，而是由生成 SQL 占位符的同一次单遍编译产出：
   - SQL + 完整参数（CTE → SELECT 投影 → WHERE → HAVING → 集合运算顺序）：
     `try_compile_with(gen)`（校验后编译）或 `compile_sql_with::<T>(gen)`
     （先解析相关子查询再校验编译）；
   - 只需要 WHERE 参数：`where_params()`。
   `all_params()` / `to_sql_with()` 仍作为兼容包装保留（等价于 portable 生成器上
   的单遍收集），但新代码请走 `try_compile_with` / `compile_sql_with`。

4. **`BoolExpr` / `HavingExpr`** 标记 `#[non_exhaustive]`；`BoolExpr` 另新增
   `Compare { left, op, right }` 变体（HAVING 下推与列算术谓词使用）。枚举变成
   non-exhaustive 后，下游穷举 `match` 需补 `_` 通配分支（这也是本次一次性破坏的
   收益：后续 AST 变体新增不再构成破坏）。

5. **移除 `ExecuteUpdateBuilder::set_column_internal`**：该别名自 2.3.0 起
   `#[deprecated]`（“更名 `set_column`，保留一个版本”），2.9 正式删除；
   动态批量更新改用 `set_column`（表达式右侧用 `set_column_expr`）。

6. **`IRow` / `IFromRow` 合并**：`row::IRow` 成为唯一行物化 trait，不再以
   `IEntityType` 为 supertrait（因此实体、`#[derive(FromRow)]` 结构体与 1..=12
   元组都直接实现它）；`from_row` 为规范入口，`from_values` 为兼容别名。
   `entity::IFromRow` 保留为兼容别名（`pub use`），但注意：
   - 下游 `T: IFromRow` 不再隐含 `IEntityType`（也不再隐含 `Send + Sync + 'static`），
     调用 `entity_meta()` / `from_row_named` 时需显式加 `T: IEntityType`；
   - 实体不再经 blanket impl 获得 `IRow`，改由 `#[derive(EntityType)]` 生成
     `impl IRow`（正常 derive 的用户代码不变）；
   - `DbContext::sql_query::<T>` 仍要求 `T: IEntityType + IRow`；
     `sql_query_rows<R: IRow>` 接受任意行类型。

7. **`compile_sql` 改为校验后返回 `EFResult<(String, Vec<DbValue>)>`**：
   `QueryBuilder::compile_sql` 在 2.6 直接返回元组并在事后从 `QueryState` 派生参数；
   2.9 校验查询状态、在同一遍编译中产出 SQL 与参数，非法状态返回 typed
   `EFError::Configuration`。调用点补 `?`（或 `map_err`）。
   `SelectQueryBuilder::compile_sql`（2.9 新增）同样返回 `EFResult`；
   `ExecuteUpdateBuilder::compile_sql()` 也是单遍校验版本（SET → WHERE 参数顺序）。
8. **`ExecuteUpdateBuilder::params()` 改为返回 `EFResult<Vec<DbValue>>`**：
   2.6 返回 `Vec<DbValue>` 且与 SQL 生成各自推导参数，非法 builder（无 SET 列）
   静默返回空向量；现在内部走 `compile_sql()` 并返回 typed error。需要 SQL 时用
   `compile_sql()`，需要执行时用 `execute()`；`params()` 仅保留给只需要参数值的调用点。

9. **`HavingExpr` / `ColumnExpr` 枚举删除（单一表达式核心）**：
   - `HavingExpr` 变为 `BoolExpr` 的兼容别名；HAVING 条件就是
     `BoolExpr::Compare`，用新增的 `BoolExpr::aggregate_compare(agg, column, op,
     value)` / `aggregate_compare_agg(...)` 构造（`linq!(having ...)` 宏直接生成）。
     原 `HavingExpr::Compare/CompareAgg/And/Or/Not` 的匹配代码改用
     `BoolExpr` 同名变体/构造器。
   - `ColumnExpr` 变为 `SqlExpr` 的兼容别名；`set_column_expr` 接受 `SqlExpr`，
     编译期校验只允许列/字面量/`+`/`-`（聚合/COALESCE/CASE 返回
     `EFError::Configuration`）。原 `ColumnExpr::Value` 用 `SqlExpr::literal`
     （或兼容的 `SqlExpr::value`），`ColumnExpr::Add/Sub` 用 `.add()`/`.sub()`。

10. **CTE 名与列名在生成 SQL 中加引号**：框架生成的标识符统一走
    `quote_identifier`（`WITH "name" ("col") AS (...)`）；调用方提供的
    FROM/表名仍按代码常量原样输出。依赖 `to_sql()` 文本做断言的代码需更新期望
    （执行语义不变）。

其它变动均为加法；`EFError` 变体、`IEntityType`（除上述超 trait 关系外）、
provider trait、迁移 API 都不变。`DbContext` 创建现在共享进程级
`Arc<BuiltMetadata>`（不再每上下文深拷贝元数据），是纯性能改进、无 API 破坏。

### 3.4 分组查询改用投影终端

`to_list()` / `count()` 现在对带 `GROUP BY`/`HAVING` 的实体查询返回
`EFError::Configuration`（此前会生成 `SELECT * ... GROUP BY`：PG/MySQL 报错，
SQLite 返回组内任意行的静默错数据）。分组报表请用：

```rust
let rows: Vec<(String, i64)> = ctx.set::<Order>().query()
    .select_items(&[SelectItem::column(Order::COLUMN_CURRENCY),
                    SelectItem::sum(Order::COLUMN_TOTAL).coalesce(0i64)])
    .group_by(&[Order::COLUMN_CURRENCY])
    .to_list_typed_2()
    .await?;
```

`select(&[...])` 与 `select_item(s)` 可以组合（列不再被静默丢弃）。

### 3.5 跨方言聚合/投影修复（无需改代码）

- MySQL：`SUM(BIGINT)` / `AVG(INT)` / DECIMAL 列现在解码为 `DbValue::Decimal`
  （此前落到 `NULL`，整数聚合静默变 0）；
- PostgreSQL：`COALESCE(SUM(...), ?)`、常量投影、CASE、HAVING 的整数/浮点参数
  会按服务端推断的 `NUMERIC`/`TEXT` 正确绑定；
- PostgreSQL：UNION/INTERSECT/EXCEPT 操作数的 `$N` 占位符会接在主查询参数之后重编号；
- 无 ON 键的非 CROSS JOIN 生成 `ON 1 = 1`（叉积），不再是悬空 `ON`。

### 3.6 幂等/限流（rust-webx 2.9）

见 rust-webx 的 CHANGELOG 与 `docs/rust-webx/11-production/idempotency.md`：
幂等键进入租户与 `ClientInfo` 客户端地址、`AllowAnonymous` 开关、租约与保留期分离；
`RateLimit.TrustProxy/TrustedProxies` 在 Production 模式会启动失败（强制迁移）。

## 4. 行为细节与边界

- **参数顺序**：完整参数向量固定为
  「CTE → SELECT 投影（literal/COALESCE/CASE）→ WHERE → HAVING → 集合运算」，
  由单遍编译（`try_compile_with` / `compile_sql_with::<T>`）在生成 SQL 占位符的
  同一次遍历中收集。HAVING 参数在编译时从 `HavingExpr` 节点按 SQL 顺序现场收集——
  既有 `linq!` 用法不变，同时修复了「先加 having 再加 filter」会导致参数错位的
  builder 用法。2.6 的 `QueryState::parameters` 字段与 `params()` 方法已删除：
  需要单独读取 WHERE 参数时用 `where_params()`，SQL + 完整参数用
  `try_compile_with` / `compile_sql_with`（`all_params()` 仅为兼容包装），
  `ExecuteUpdateBuilder::params()` 保留但改为返回 `EFResult<Vec<DbValue>>`
  （规范入口 `compile_sql()` / `execute()`）。
  内置终端已经这样处理。
- **空组/NULL**：投影聚合不做隐式 `COALESCE`。`SUM/AVG` 在「全 NULL 组」、
  `MIN/MAX` 在空组仍是 SQL NULL，类型化解码返回带字段名/序号的
  `EFError::TypeConversion`；需要中性值就显式
  `SelectItem::sum(col).coalesce(0)`。标量终端 `sum -> f64` 的空集归零
  （EF-17）保持不变。
- **数值聚合的方言细节**：PostgreSQL 的 `SUM(bigint)`/`AVG(int)` 返回 `NUMERIC`；
  2.9 的解码层接受「整值 NUMERIC → 整数目标」，非整值解码到 `i64` 会报 typed
  `TypeConversion`（不会静默截断）；小数结果用 `avg_as::<f64>` 或 `Decimal`。
  SQLite 的 `AVG` 始终是 REAL，`avg_as::<i64>` 会得到 `TypeConversion`。
- **JOIN 边界**：ON 只表达等值键（复合键用多个 key）；同表自连接没有表别名，
  请用原生 SQL + `IRow`；从 CTE 起步的 join 第二跳用 `join_from` 显式给左表。
- **`linq!` select**：仍支持 `select (a.col, b.col)`——**纯列** select 生成的 SQL
  与 2.6 逐字符一致；新增 `sum/avg/min/max(...)`、`count()`、`count(col)` 聚合项，
  一旦出现聚合项就走类型化投影路径（列项输出为 `expr AS 列名`，别名可用于
  `order_by`），列项 + 聚合项按书写顺序生成 SELECT 列表。
- **`to_list_rows` / `#[derive(FromRow)]`**：按位置映射，`SELECT` 列顺序必须与
  结构体字段顺序一致（provider 不返回列名）；行长度必须与字段数**完全相等**
  （缺列与多列都报 typed `TypeConversion`，避免 SELECT 列表漂移被静默忽略）。
  可空列用 `Option<T>` 字段（SQL NULL → `None`，LEFT JOIN 报表可直接映射）。
  实体继续用 `sql_query::<T>`（`IEntityType + IRow`；`IFromRow` 为兼容别名，
  位置/命名两路径都保留）。

## 5. 从原生 SQL 收口（推荐步骤）

1. 把报表 SQL 的 WHERE 部分换成 `linq!` 谓词（租户/权限条件仍由服务端最先 AND）；
2. `GROUP BY` + 聚合列换成 `group_by` + `select_items`（或 `linq!` 的
   `select (...)` 聚合项），按需 `.coalesce(0)`；
3. 删掉手工 `Vec<Vec<DbValue>>` 逐格 `try_from`，改为
   `#[derive(FromRow)]` + `to_list_rows` / `sql_query_rows`；
4. `SET col = col + 1` 改为 `increment`/`set_column_expr`，与
   `#[concurrency_check]`/CAS `WHERE version = ?` 同一条语句；
5. 复合/链式 JOIN 改为 `linq!` 复合条件或 `join`/`join_from`，
   被 join 表过滤改用 `filter_joined`；
6. 收口后删除 `// raw-sql:` 登记（只保留真正的探针/迁移元数据）。
