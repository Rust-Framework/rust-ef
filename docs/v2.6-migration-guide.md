# rust-ef 2.6 迁移指南：移除 webx feature，错误映射回到应用边界

> 适用：`2.5.x → 2.6.0`。本版本是 2.x 内的破坏性变更：`rust-ef` 不再提供可选 feature
> `webx`，也不再依赖 `rust-webx-core`。rust-webx / rust-dix 的版本不在本指南范围内；
> `EFError` 的变体与其余 ORM API 不变。

## 1. 变更

| 2.5.x | 2.6.0 |
|---|---|
| `rust-ef = { features = ["webx"] }` | 删除 feature；`EFError` 映射在应用侧 |
| `impl From<EFError> for webx::Error` | 应用侧 `map_ef_error` + `EfResultExt::map_ef` |
| 可选依赖 `rust-webx-core ^1.2`（与 webx 2.x 不同主版本） | 无跨框架依赖；依赖图只有一份 `rust-webx-core 2.5.0` |
| `?` 直接把 `EFError` 转成 `webx::Error` | 调用点写 `.map_ef()?` |

## 2. 迁移步骤

1. **依赖**：从 `rust-ef` 依赖删除 `features = ["webx"]`；删除为旧 1.x 依赖加的
   `[patch.crates-io] rust-webx-core = ...` 与 `compat/webx-core-shim` 目录。
2. **应用侧统一映射**：在共享层（例如 `handlers/src/common_mapper.rs`）写一次：

   ```rust
   use ef::error::EFError;
   use webx::Error;

   pub fn map_ef_error(error: EFError) -> Error {
       // NotFound 404；ModelValidation/Query/TypeConversion 400；
       // ConcurrencyConflict/UniqueViolation 409（不回显 constraint/table）；
       // Connection/Transaction 503；其余 500 且 public_detail() = None
       // 完整实现见下节映射表
   }

   pub trait EfResultExt<T> {
       fn map_ef(self) -> Result<T, Error>;
   }

   impl<T> EfResultExt<T> for Result<T, EFError> {
       fn map_ef(self) -> Result<T, Error> {
           self.map_err(map_ef_error)
       }
   }
   ```

3. **调用点**：把所有 `DbContext` 调用的 `?` 改成 `.map_ef()?`；组合子或启动/迁移等
   非请求期代码继续用 `map_ef_error` 函数值。
4. **清理引用**：删除 `ef::webx::*`、`rust_ef::webx::*` 与对 shim 的引用。
5. **验证**：

   ```text
   cargo tree -e features -i rust-ef      # 不出现 webx feature
   cargo tree -i rust-webx-core           # 只有 2.5.0（没有 1.x）
   cargo test --workspace
   ```

## 3. 映射语义

| `EFError` | HTTP | `webx::Error` | 客户端可见 detail |
|---|---|---|---|
| `NotFound` | 404 | `NotFound` | 调用方业务文案（原样） |
| `ModelValidation` | 400 | `Validation` | 调用方业务文案（原样） |
| `ConcurrencyConflict` | 409 | `Conflict` | 调用方业务文案（原样） |
| `Query`、`TypeConversion` | 400 | `Validation` | 固定文案（不泄露 SQL/列名） |
| `UniqueViolation` | 409 | `Conflict` | 固定文案（不泄露 constraint/table） |
| `Connection`、`Transaction` | 503 | `Status(503, _)` | 固定文案（不泄露连接串/口令） |
| `Database` | 500 | `Internal` | 无（结构化驱动错误只进日志） |
| `Migration`、`Configuration`、`Provider`、`ChangeTracking`、`Other` | 500 | `Internal` | 无（`public_detail() = None`，原文与 `source` 链只进日志） |

## 4. 兼容性说明

- **默认 feature 集不变**：`serde` / `chrono` / `uuid` / `decimal` / `tracing` 仍按需开启；
  关闭时依然零可选依赖。
- **业务错误构造不变**：`EFError::{not_found, model_validation, concurrency_conflict,
  unique_violation, connection, ...}` 的签名与语义不变。
- **`EFError` 仍不是 `#[non_exhaustive]`**：下游穷举 `match` 需补 `_ => …`。
- **不要恢复跨框架桥接**：`impl From<EFError> for webx::Error` 在应用侧因孤儿规则
  （E0117）不可实现；`rust-ef` 也不应重新依赖 Web 框架。若未来需要框架级集成，
  按 webx → ef 的方向评审（webx 侧可选 feature 或独立集成 crate）。
