# rust-ef 2.7 迁移指南：报表查询与集合写对象化

> 适用：`2.6.x → 2.7.0`（minor，纯加法为主）。
> 逐条完整说明见仓库根 [CHANGELOG.md](../CHANGELOG.md)；
> 新 API 的用法见 [类型化投影与报表行](rust-ef/06-advanced-query/typed-projections.md)
> 与 [GROUP BY 与 HAVING](rust-ef/06-advanced-query/group-by-having.md)。

## 1. 一句话结论

2.7.0 把「分组聚合报表、整数/Decimal 精确聚合、复合/链式 JOIN、`col = col + 1`
更新、任意结果行物化」从原生 SQL 搬回对象 API。已有代码**不需要改**；
只有直接构造 `JoinSpec`/`QueryState` 两个公开结构体的极少数代码需要按 §3 调整。

## 2. 新能力速查（不改旧代码）

| 需求 | 2.7.0 写法 |
|---|---|
| 分组报表：组键 + 聚合 + 别名 + 排序 + 限量 | `ctx.set::<Order>().query().filter(pred).group_by(&[Order::COLUMN_CURRENCY]).select_items(&[SelectItem::column(Order::COLUMN_CURRENCY), SelectItem::sum(Order::COLUMN_TOTAL).alias("total")]).order_by_desc("total").take(20).to_list_rows::<RevenueRow>().await?` |
| `linq!` 里写分组聚合 | `linq!(ctx.set::<Order>(), \|o: Order\| o.tenant_id == t; group_by o.currency; select (o.currency, sum(o.total_amount), count()))` 返回 `SelectQueryBuilder`，再 `.to_list_typed_3::<String, i64, i64>().await?` |
| 整数/Decimal 精确求和 | `let total: i64 = linq!(ctx.set::<Order>(); sum_i64 o.total_amount).await?;` 或 `sum_as::<i64>(col)` / `avg_as::<f64>(col)` |
| 报表行（非实体） | `#[derive(FromRow)] struct RevenueRow { currency: String, total: i64 }` + `to_list_rows::<RevenueRow>()` / `ctx.sql_query_rows::<RevenueRow>(sql, params)` |
| 复合键 JOIN | `linq!(...; inner_join \|o: Order, s: Shipment\| o.id == s.order_id && o.region_id == s.region_id)`；运行时 `query().join::<Shipment>(JoinKind::Inner, &[("id", "order_id"), ("region_id", "region_id")])` |
| 链式 JOIN | 连续多个 join 子句（`inner_join \|s: Shipment, n: Note\| ...`），或运行时 `join_from::<Note, Shipment>(JoinKind::Inner, &[...])` |
| 过滤被 join 表 | `query().filter_joined::<Shipment>(linq!(\|s: Shipment\| s.carrier == "UPS"))`（自动限定为 `shipments.carrier`） |
| `col = col + 1` / 扣减库存 | `execute_update().increment(Order::COLUMN_VERSION, 1)` / `.decrement(Order::COLUMN_STOCK, qty)` / `.set_column_expr(Order::COLUMN_TOTAL, ColumnExpr::column(Order::COLUMN_TOTAL).add(ColumnExpr::column(Order::COLUMN_DISCOUNT)))` |
| `linq!` 表达式更新 | `linq!(...; set o.version, o.version + 1; execute_update)` |

## 3. 破坏性/可观测边界变化

> 本节两项是**源码级破坏**（仅影响直接构造结构体字面量/直接使用 `QueryState` 的代码），
> builder API 全部为加法。

1. **`JoinSpec`**：`{ join_type: String, table: String, on_clause: String }`
   → `{ kind: JoinKind, table: String, keys: Vec<JoinKey> }`。
   框架内部与 `linq!` 已全部改走 builder；直接构造 `JoinSpec` 的三方代码改为
   `QueryBuilder::{join, join_from}` 或按新字段构造（`JoinKey { left_table, left_column, right_column }`）。
   旧 `inner_join_internal` / `left_join_internal` / ... 仍保留，生成 SQL 逐字符不变。
2. **`QueryState`** 新增公开字段 `projections: Vec<SelectItem>`。
   用 `QueryState::new(table)` 构造的代码不受影响；结构体字面量构造需补
   `projections: Vec::new()`（推荐改用 `QueryState::new`）。

3. **`QueryState::params()`** 只返回 WHERE 参数（2.6 还包含 HAVING）；完整参数
   用 `all_params()`，见 §4。

其它变动均为加法；`EFError` 变体、`IEntityType`/`IFromRow`、provider trait、
迁移 API 都不变。

### 3.4 分组查询改用投影终端

`to_list()` / `count()` 现在对带 `GROUP BY`/`HAVING` 的实体查询返回
`EFError::Configuration`（此前会生成 `SELECT * ... GROUP BY`：PG/MySQL 报错，
SQLite 返回组内任意行的静默错数据）。分组报表请用：

```rust
let rows: Vec<(String, i64)> = ctx.set::<Order>().query()
    .select_items(&[SelectItem::column(Order::COLUMN_CURRENCY),
                    SelectItem::sum(Order::COLUMN_TOTAL).coalesce(0i64)])
    .group_by(&[Order::COLUMN_CURRENCY])
    .to_list_typed_2()
    .await?;
```

`select(&[...])` 与 `select_item(s)` 可以组合（列不再被静默丢弃）。

### 3.5 跨方言聚合/投影修复（无需改代码）

- MySQL：`SUM(BIGINT)` / `AVG(INT)` / DECIMAL 列现在解码为 `DbValue::Decimal`
  （此前落到 `NULL`，整数聚合静默变 0）；
- PostgreSQL：`COALESCE(SUM(...), ?)`、常量投影、CASE、HAVING 的整数/浮点参数
  会按服务端推断的 `NUMERIC`/`TEXT` 正确绑定；
- PostgreSQL：UNION/INTERSECT/EXCEPT 操作数的 `$N` 占位符会接在主查询参数之后重编号；
- 无 ON 键的非 CROSS JOIN 生成 `ON 1 = 1`（叉积），不再是悬空 `ON`。

### 3.6 幂等/限流（rust-webx 2.8）

见 rust-webx 的 CHANGELOG 与 `docs/rust-webx/11-production/idempotency.md`：
幂等键进入租户与 `ClientInfo` 客户端地址、`AllowAnonymous` 开关、租约与保留期分离；
`RateLimit.TrustProxy/TrustedProxies` 在 Production 模式会启动失败（强制迁移）。

## 4. 行为细节与边界

- **参数顺序**：完整参数向量固定为
  「CTE → SELECT 投影（literal/COALESCE/CASE）→ WHERE → HAVING → 集合运算」。
  HAVING 参数改为在 `all_params()` 时从 `HavingExpr` 节点现场收集——既有
  `linq!` 用法不变，同时修复了「先加 having 再加 filter」会导致参数错位的
  builder 用法。`QueryState::params()` 的语义有边界变化：2.6 还包含 HAVING 参数，
  2.7 起只返回 WHERE 参数（HAVING 在 `all_params()` 里按 SQL 顺序现场收集）；
  查询带 HAVING 时请用 `all_params()`，内置终端已经这样处理。
- **空组/NULL**：投影聚合不做隐式 `COALESCE`。`SUM/AVG` 在「全 NULL 组」、
  `MIN/MAX` 在空组仍是 SQL NULL，类型化解码返回带字段名/序号的
  `EFError::TypeConversion`；需要中性值就显式
  `SelectItem::sum(col).coalesce(0)`。标量终端 `sum -> f64` 的空集归零
  （EF-17）保持不变。
- **数值聚合的方言细节**：PostgreSQL 的 `SUM(bigint)`/`AVG(int)` 返回 `NUMERIC`；
  2.7 的解码层接受「整值 NUMERIC → 整数目标」，非整值解码到 `i64` 会报 typed
  `TypeConversion`（不会静默截断）；小数结果用 `avg_as::<f64>` 或 `Decimal`。
  SQLite 的 `AVG` 始终是 REAL，`avg_as::<i64>` 会得到 `TypeConversion`。
- **JOIN 边界**：ON 只表达等值键（复合键用多个 key）；同表自连接没有表别名，
  请用原生 SQL + `IRow`；从 CTE 起步的 join 第二跳用 `join_from` 显式给左表。
- **`linq!` select**：仍支持 `select (a.col, b.col)`——**纯列** select 生成的 SQL
  与 2.6 逐字符一致；新增 `sum/avg/min/max(...)`、`count()`、`count(col)` 聚合项，
  一旦出现聚合项就走类型化投影路径（列项输出为 `expr AS 列名`，别名可用于
  `order_by`），列项 + 聚合项按书写顺序生成 SELECT 列表。
- **`to_list_rows` / `#[derive(FromRow)]`**：按位置映射，`SELECT` 列顺序必须与
  结构体字段顺序一致（provider 不返回列名）；行长度必须与字段数**完全相等**
  （缺列与多列都报 typed `TypeConversion`，避免 SELECT 列表漂移被静默忽略）。
  可空列用 `Option<T>` 字段（SQL NULL → `None`，LEFT JOIN 报表可直接映射）。
  实体继续用 `sql_query::<T>`（`IFromRow`，位置/命名两路径都保留）。

## 5. 从原生 SQL 收口（推荐步骤）

1. 把报表 SQL 的 WHERE 部分换成 `linq!` 谓词（租户/权限条件仍由服务端最先 AND）；
2. `GROUP BY` + 聚合列换成 `group_by` + `select_items`（或 `linq!` 的
   `select (...)` 聚合项），按需 `.coalesce(0)`；
3. 删掉手工 `Vec<Vec<DbValue>>` 逐格 `try_from`，改为
   `#[derive(FromRow)]` + `to_list_rows` / `sql_query_rows`；
4. `SET col = col + 1` 改为 `increment`/`set_column_expr`，与
   `#[concurrency_check]`/CAS `WHERE version = ?` 同一条语句；
5. 复合/链式 JOIN 改为 `linq!` 复合条件或 `join`/`join_from`，
   被 join 表过滤改用 `filter_joined`；
6. 收口后删除 `// raw-sql:` 登记（只保留真正的探针/迁移元数据）。
