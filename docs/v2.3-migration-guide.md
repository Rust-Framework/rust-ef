# rust-ef 2.3 迁移指南（EFCore 实体配置对齐）

适用对象：从 **2.2.x** 升级到 **2.3**，或需要把 `HasColumnType` / `HasPrecision` / `HasComment` / `HasComputedColumnSql` / `UseCollation` / `ToView` / `HasNoKey` / `HasAlternateKey` / `ToTable(schema)` / 枚举转换从业务代码迁回框架配置的应用。

## 1. 依赖调整

```toml
[dependencies]
rust-ef = "2.3"
rust-ef-sqlite = "2.3"   # 或 postgres / mysql，保持同版本
```

`rust-dix` 仍为 `0.10`，MSRV 仍为 **1.95**。

## 2. 兼容性

| 变更 | 影响 | 迁移 |
|---|---|---|
| `PropertyMeta` 新增 `column_type` / `precision` / `scale` / `is_fixed_length` / `collation` / `comment` / `computed_sql` / `computed_stored` / `default_value` | 手写 `PropertyMeta` 字面量缺字段 | 补字段或改用 `PropertyMetaBuilder` |
| `EntityTypeMeta` 新增 `is_view` / `is_keyless` / `comment`；移除侧表 `column_defaults` | 同上 | 补 `..EntityTypeMeta::default()`；默认值改用 `property_named(...).has_default(...)` |
| `SnapshotColumn` / `SnapshotEntityType` / `SnapshotIndex` 新增字段 | 手写快照字面量缺字段 | 补 `..Default::default()` |
| 计算列不再出现在 INSERT/UPDATE | 以前手写计算列会被写入 | 现在由数据库生成，符合预期 |

## 3. 新能力速查

### 3.1 列类型 / 精度 / 定长 / 排序规则 / 注释

```rust
entity.property_named("payload").has_column_type("JSON");
entity.property_named("price").has_precision(12, 2);
entity.property_named("currency").is_fixed_length().has_max_length(3);
entity.property_named("code").has_collation("utf8mb4_bin").has_comment("业务编码");
```

派生属性等价：`#[column_type("JSON")]`、`#[precision(12,2)]`、`#[fixed_length]`、`#[collation("...")]`、`#[comment("...")]`。

### 3.2 计算列

```rust
entity
    .property_named("total")
    .has_computed_column_sql("unit_price * quantity")
    .is_stored();
// 或派生：#[computed("unit_price * quantity", stored)]
```

计算列自动从 INSERT/UPDATE 排除；SQLite/MySQL 支持，PostgreSQL 必须 STORED。

### 3.3 表注释 / 视图 / 无键 / schema

```rust
entity.has_comment("订单表");
entity.to_view("v_order_summary");   // 不生成建表 DDL
entity.has_no_key();                 // 无主键
entity.to_schema("shop");            // "shop"."orders"
```

派生等价：`#[table("orders", comment = "...")]`、`#[table("v", view)]`、`#[keyless]`、`#[table("orders", schema = "shop")]`。

### 3.4 备用键 / INCLUDE

```rust
entity.has_alternate_key(&[Order::COLUMN_TENANT_ID, Order::COLUMN_NO]);
entity.has_index(&[Order::COLUMN_TENANT_ID]).include(&[Order::COLUMN_STATUS]);
```

INCLUDE 仅 PostgreSQL 生效；MySQL/SQLite 输出 warning 并忽略。

### 3.5 枚举转换 `DbEnum`

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, rust_ef::DbEnum)]
pub enum OrderStatus {
    #[default]
    Pending,
    #[db_value("PAID")]
    Paid,
}
```

枚举字段、`linq!` 过滤和行物化直接可用；需同时 `derive(Default)`。

## 4. 自动升级（下一次迭代加字段）

```rust
// 应用内 snapshot 子命令（CLI 看不到 inventory 模型）
rust_ef::migration::save_registered_snapshot(
    "current_snapshot.json",
    None,
    rust_ef::migration::MigrationDialect::MySql,
)?;
```

```bash
rust-ef migration add AddStock --snapshot current_snapshot.json --dir Migrations --dialect mysql
```

```rust
// 启动时应用（等价 EF Core Database.Migrate()）
let applied = ctx.migrate("Migrations").await?;
```

- PostgreSQL/SQLite 的迁移脚本（含历史行）原子执行，失败回滚；MySQL DDL 隐式提交。
- 新增可空列/带默认值列全自动；无默认值的 NOT NULL 列会输出警告（非空表需回填）。
- SQLite 对既有表增删 FK/CHECK 会输出 warning（需重建表）。
- 完整步骤见 [自动升级流程](rust-ef/09-transactions-migrations/auto-upgrade.md)。

## 5. 验收清单

- `cargo test -p rust-ef --all-features --test entity_config_tests` 通过；
- `cargo test -p rust-ef --all-features --test migration_automation_tests` 通过；
- MySQL/PG 首装 DDL 含 schema 限定、列类型覆盖、注释、计算列；
- 视图实体不出现在 `CREATE TABLE`，`ensure_deleted` 不删除视图；
- 业务侧不再手写 enum `From/TryFrom<DbValue>` 或自定义 DDL。
