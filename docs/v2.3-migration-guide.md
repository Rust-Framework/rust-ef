# rust-ef 2.3.0 迁移指南（简版）

> 基线：2.2.0 → 2.3.0（minor，只做加法 + 两处行为变更）。逐条完整说明见仓库根 [CHANGELOG.md](../CHANGELOG.md)；运行时升级流程见 [自动升级流程](rust-ef/09-transactions-migrations/auto-upgrade.md)。

## 新增能力速览（每条一句）

| 能力 | 入口 | 一句话 |
|---|---|---|
| 连接串解析 / 构造 / 校验 | `rust_ef::connection_string::ConnectionString`（`parse` / `validate` / `build`，userinfo 百分号编码往返）与 `ProviderKind`（URL scheme / 默认端口 / 迁移方言） | 不再手写连接串拼接与端口/协议校验 |
| provider 统一内省 | `IDatabaseProvider::introspect()`（三方言都实现，返回 `rust_ef::schema::DbTable`） | 安装器/升级流程不再按方言分派内省 |
| history-free 安装 | `DbContext::bootstrap()`、`MigrationEngine::bootstrap` / `bootstrap_with_seed` | 空库建全量 schema（含索引/外键）且不写 `__ef_migrations_history`，`bootstrap → seed` 一条路径 |
| 运行期模型差分 | `MigrationEngine::diff_metas(...) -> MigrationDiff` + `apply_diff`（或 `diff(&ModelSnapshot, ...)`） | 已装库按模型自动对齐；只自动做加法，删除类变更只告警 |
| 查询 / 物化 / 更新入口 | `IFromRow::from_row_named`、`ExecuteUpdateBuilder::set_column`、`ISaveChangesInterceptor::on_saving_mut` + `AuditInterceptor` | 按列名物化、动态列/CAS、服务端审计字段自动填充 |

## 升级时要处理的兼容点（2 处）

1. **`EFError` 新增 `UniqueViolation` 变体**：`EFError` 未加 `#[non_exhaustive]`，下游穷举 `match` 需补一个分支（显式处理或 `_ => ...`）。
2. **provider 的旧 `DbTable` / `DbColumn` 被 `rust_ef::schema::*` 替换**：`rust_ef_mysql::DbTable`、`rust_ef_postgres::DbTable` 现在是 `schema::DbTable` 的 re-export（字段更多）；只读字段不受影响，**结构体字面量构造**需补新字段，或改用 `DbTable::new(name)` 再逐字段赋值。

## 行为变更（升级前检查）

- **EF-12 必填性推断**：`Option<T>` → 可空，其它标量 → `NOT NULL`。已装库不受影响，但旧快照对新模型 diff 会报 `NULL → NOT NULL`；请重新导出 `model_snapshot.json` 并 review 首个迁移。详见 [EntityType 派生与属性配置](rust-ef/03-entity-design/derive-attributes.md)。
- **EF-10 脚本顺序**：生成脚本改为 `CREATE TABLE → CREATE INDEX → ADD CONSTRAINT` 分段（语义不变，MySQL 外键不再因索引顺序失败）。

## 弃用

- `ExecuteUpdateBuilder::set_column_internal` → `set_column`（旧名保留一版 `#[deprecated]` 别名）。见 [批量更新](rust-ef/08-bulk-operations/execute-update.md)。
