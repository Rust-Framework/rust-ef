# v1.8.0 迁移指南

> 版本：v1.8.0 — 2026-07-10
> 适用范围：rust-ef workspace 全部 crate（core / sqlite / postgres / mysql / macros / cli）
> 变更性质：**Breaking Change** — ChangeTracker 架构重设计 + EntitySnapshot 类型引入

---

## 概述

v1.8.0 是深度性能优化迭代，包含两项架构级变更：

1. **EntitySnapshot 类型**：`snapshot()` / `key_values()` 返回类型从 `HashMap<String, DbValue>` 改为 `EntitySnapshot`（`Box<[(&'static str, DbValue)]>`），消除每次调用的 HashMap 分配 + N 个 String 键分配。
2. **ChangeTracker 单一跟踪源**：跟踪状态（state, original snapshot, modified_properties）从 `DbSet` 内联移至 `ChangeTracker`，`DbSet` 仅持有 `entity + entry_id`。变更操作入口从 `DbSet` 移至 `DbContext`。

---

## 1. DbContext API 变更（影响最大）

### 1.1 变更方法调用位置

所有实体变更操作（add / attach / update / upsert / remove_at / remove_all）从 `DbSet` 方法移至 `DbContext` 方法。

**Before (v1.7.x)**:
```rust
ctx.set::<Blog>().add(blog);
ctx.set::<Blog>().attach(blog);
ctx.set::<Blog>().update(blog);
ctx.set::<Blog>().upsert(blog);
ctx.set::<Blog>().remove_at(idx)?;
ctx.set::<Blog>().remove_all();
ctx.set::<Blog>().detect_changes();
ctx.set::<Blog>().load_all().await?;
```

**After (v1.8.0)**:
```rust
ctx.add::<Blog>(blog);
ctx.attach::<Blog>(blog);
ctx.update::<Blog>(blog);
ctx.upsert::<Blog>(blog);
ctx.remove_at::<Blog>(idx)?;
ctx.remove_all::<Blog>();
ctx.detect_changes();
ctx.load_all::<Blog>().await?;
```

### 1.2 查询方法不变

查询方法仍在 `DbSet` 上：
```rust
// 这些调用方式不变
ctx.set::<Blog>().query().to_list().await?;
ctx.set::<Blog>().filter(linq!(...)).to_list().await?;
ctx.set::<Blog>().query().find(id).await?;
ctx.set::<Blog>().query().count().await?;
ctx.set::<Blog>().tracked_entries_mut();
ctx.set::<Blog>().clear_entries();
```

### 1.3 批量替换

如果项目中有大量旧 API 调用，可使用以下正则表达式批量替换：

| Pattern | Replacement |
|---------|-------------|
| `\.set::<(\w+)>\(\)\.add\(` | `.add::<$1>(` |
| `\.set::<(\w+)>\(\)\.attach\(` | `.attach::<$1>(` |
| `\.set::<(\w+)>\(\)\.update\(` | `.update::<$1>(` |
| `\.set::<(\w+)>\(\)\.upsert\(` | `.upsert::<$1>(` |
| `\.set::<(\w+)>\(\)\.remove_at\(` | `.remove_at::<$1>(` |
| `\.set::<(\w+)>\(\)\.remove_all\(\)` | `.remove_all::<$1>()` |
| `\.set::<(\w+)>\(\)\.detect_changes\(\)` | `.detect_changes()` |
| `\.set::<(\w+)>\(\)\.load_all\(\)` | `.load_all::<$1>()` |

## 2. snapshot() / key_values() 返回类型变更

### 2.1 类型变更

`IEntitySnapshot::snapshot()` 和 `IGetKeyValues::key_values()` 的返回类型从 `HashMap<String, DbValue>` 改为 `EntitySnapshot`。

```rust
// Before (v1.7.x)
fn snapshot(&self) -> HashMap<String, DbValue>;
fn key_values(&self) -> HashMap<String, DbValue>;

// After (v1.8.0)
fn snapshot(&self) -> EntitySnapshot;
fn key_values(&self) -> EntitySnapshot;
```

### 2.2 宏生成实体（#[derive(EntityType)]）

**无需手动改动**。宏自动生成 `EntitySnapshot::new(vec![...])` 形式的实现。

### 2.3 手动 impl 迁移

如果手动实现了 `IEntitySnapshot` 或 `IGetKeyValues`，需要更新返回类型：

**Before**:
```rust
impl IEntitySnapshot for MyEntity {
    fn snapshot(&self) -> HashMap<String, DbValue> {
        let mut map = HashMap::new();
        map.insert("id".to_string(), DbValue::I32(self.id));
        map.insert("name".to_string(), DbValue::String(self.name.clone()));
        map
    }
}
```

**After**:
```rust
impl IEntitySnapshot for MyEntity {
    fn snapshot(&self) -> EntitySnapshot {
        EntitySnapshot::new(vec![
            ("id", DbValue::I32(self.id)),
            ("name", DbValue::String(self.name.clone())),
        ])
    }
}
```

### 2.4 调用点适配

`EntitySnapshot` 提供 `get()` / `iter()` / `len()` / `is_empty()` 方法，API 与 `HashMap` 类似但语义为不可变：

```rust
// Before
let snap = entity.snapshot();
let id = snap.get("id").cloned();  // Option<&DbValue> → clone

// After — API 几乎相同
let snap = entity.snapshot();
let id = snap.get("id").cloned();  // Option<&DbValue> → clone
```

## 3. save_one_set 移除

`rust_ef::db_context::save_one_set()` 函数已移除。该函数用于独立 `DbSet`（不通过 `DbContext`）的保存操作。

**Before**:
```rust
let mut db_set = DbSet::<T>::with_provider("table", provider);
db_set.add(entity);
let (added, _, _) = save_one_set(&mut *conn, &*provider, &mut db_set, &meta).await?;
```

**After**:
```rust
let mut ctx = DbContext::from_options(&options)?;
ctx.set::<T>();
ctx.ensure_created().await?;
ctx.add::<T>(entity);
let result = ctx.save_changes().await?;
assert_eq!(result.added, 1);
```

## 4. ChangeTracker API 变更（内部）

> 仅影响直接操作 `ChangeTracker` 的测试代码或高级用法。

| Before | After |
|--------|-------|
| `tracker.track_entity(type_id, "Name", state)` | `tracker.track(type_id, "Name", state, None, false)` |
| `tracker.accept_all_changes()` | `tracker.accept_all_changes(&[])` |
| `db_set.entries_with_state()` | `ctx.change_tracker().entries()` (然后 filter state) |

## 6. 变更收益

| 优化项 | Before (v1.7.x) | After (v1.8.0) | 收益 |
|--------|-----------------|-----------------|------|
| `snapshot()` 分配 | 1 HashMap + N String 键 + N DbValue clone | 1 Box<[T]> + N DbValue clone | 消除 HashMap + N String 分配 |
| `key_values()` 分配 | 同上 | 同上 | 同上 |
| per-row UPDATE sql_cache | HashMap 键分配（命中率 ≈ 0%） | 直接调用 gen.update() | 消除 2 String + 1 Vec 分配/行 |
| ChangeTracker String 残余 | PropertySnapshot{serialized: String} 死代码 | 已删除 | 代码清理 |
